## 附 A：裁决与偏差

### A-1 golden 基线
见 P5-0.0-b：无硬编码基线 ⇒ T1/T2 只需跑通并记录 hash 作为证据。

### A-2 **计划 M5 的阈值不可达，已改写**
计划 §6.2 M5 = 「`land_h > 0.6` 且局地起伏 < `plateau_max_relief` 的比例」。但 `sea_level = 0.64`、`E ≤ 1`
⇒ `land_h ≤ 0.36`，**候选集恒为空**（实测 `land_h_max` = 0.3333–0.3384，40 个种子无一例外；M5 恒为 0）。
改为 **M5_p90** = 「`land_h ≥ p90(land_h)` 的高地格中，`max−min`(自身+6邻) < 0.02 的比例」。
（`ridge-metrics` 独立得出同一结论，并保留字面 M5 为 SKIP + 打印 `land_h_max` 作证据。）

### A-3 **M1 是弱判别量，且新算法下变差**
计划预计基线 M1 ≈ 0、目标 ≤ −0.3。实测基线已是 **−0.2863 / −0.3485**（脊噪声本就落在低汇水格上）。
新算法下变成 **−0.2669 / −0.3025**，即**两档都变「正」= 变差**。
机理：`ridge_add` 是**静态噪声场**，它与「最终地表 log 汇水面积」的相关性主要由最终水系决定；
把抬升放进 SPL 只改变高程分布，不改变二者的符号关系。扫描显示要把 M1 推到 ≤ −0.3 需 u ≈ 0.10，
但那会把 p90 抬到基线 +23% 并让闭合洼地回升（见 B-1）。
**建议下一轮**：改成「只在分水岭格上施加抬升」或「抬升场随汇水面积自反馈」，而不是静态噪声场。

### A-4 计划外的一处标定改动（已披露）
`spl_uplift_rate` **0.10 → 0.08**。理由：新增的 `spl_ridge_uplift·ridge_add` 叠加在原有
`spl_uplift_rate·relief0` 抬升项上，会把陆地高度整体抬高；下调这一项把分布拉回基线
（p90 小图 +25%→+14%）。这是标定 `spl_ridge_uplift` 的必要配套，已同步 C++ 兜底与测试 profile 三处。

### A-5 `ridge_debug_dump` 不做成 ClimateProfile export
它是测试/诊断用开关，只经 raw profile dict 传入；放进玩家可见的 `ClimateProfile` 没有价值还会污染调参面板。
