## 0. 设计目标

现在的理念是“全国某项 +x%”的平铺加法，卡与卡之间只有“A+B 同时装备再加一点”的固定组合。
新设计要做到：

1. **一张卡制造条件，另一张卡吃这个条件**：例如“铁矿石 +15%”让更多地块的主产物变成铁，
   “主产铁的地块让周围工业 +10%”才开始大量命中。
2. **效果落在地图上**：大部分效果按地块判断、按邻格/范围扩散，玩家的布局和地图本身就是 build 的一部分。
3. **两个乘区**：普通卡给 +%（同区相加，越多越平），传奇卡给 ×（独立相乘，成形后爆发）。
4. **升级改规则**：L2 主要放大数值或范围；L3 追加一条新子句，而不是单纯把数字乘 2.2。
5. **代价也是条件化的**：例如“这些地块农业 -10%”，让代价同样成为布局问题。

## 1. 标签词典（卡牌之间的共享语言）

所有卡的条件都只引用下列标签。阈值一律带 **5 个百分点的滞回**（进入 ≥50%，退出 <45%），
避免“加成把占比推过线 → 线下失效 → 再掉回去”的来回抖动。

| 标签 | 精确定义 | 数据来源 |
|---|---|---|
| 主产〔X〕 | 地块产出最多的物资是 X | 现有 metric 45 `cell.dominant_output_good_id` |
| 专精 | 主产物占地块总产出 ≥60%（“高度专精”≥80%） | 现有 metric 46 `cell.top_output_good_share_q16` |
| 粮作 | 主产物属于 小麦/稻米/玉米/马铃薯/谷物 | metric 45 + 编译期物资分组 |
| 支柱〔部门〕 | 农业/矿业/工业/能源/知识 中某部门产出占地块 ≥50% | 现有 metric 37–41（按产出，不按建筑数） |
| 富藏〔R〕 | 主导资源为 R 且存量占比 ≥50% | 现有 metric 43/44 |
| 多元 | 地块内有建筑的部门数 ≥3 | 现有 metric 25 `cell.distinct_sector_count` |
| 成链 | 地块内完整产业链 ≥1 条 | 现有 metric 28 `cell.complete_chain_count` |
| 繁市 | 地块贸易事件数 ≥ 繁市阈值 T | 现有 metric 8 `cell.trade_events` |
| 边地 / 聚落 / 大邑 | 人口 < P0 / ≥ P1 / ≥ P2 | 现有 metric 9 `cell.population` |
| 失业 | 失业率 ≥10% | 现有 metric 22 `cell.unemployment_q16` |
| 短缺 | 必需品短缺 ≥20% | 现有 metric 11 `cell.essentials_shortage_q16` |
| 富饶 / 枯竭 | 资源丰度 ≥80% / 资源短缺 ≥30% | 现有 metric 14 / 7 |
| 地貌〔L〕 | 地块地貌为 L（丘陵、三角洲、河谷、海岸……） | 现有 metric 10，或全国地貌限定乘区 |
| 降雨日 | 当日发生降雨事件 | 现有 metric 13 `cell.rain_event` |
| 计邻 | 相邻（或 N 格内）满足条件的地块数 | **新增 X2** |
| 连片 / 矿区 | 同条件地块组成的连通块大小 | **新增 X2** |
| 职业占比 | 某职业或职业类占地块人口比例 | **新增 X3** |
| 新增 | 某职业人数/职业种类在本次结算中增加 | **新增 X4** |

阈值 P0/P1/P2/T 不写死，按“开局后 50 年存档的自有地块分布”标定：
边地 = 人口 30 分位，聚落 = 70 分位，大邑 = 90 分位，繁市 = 贸易事件 75 分位。

地块级效果统一写到 ideology 专属的地块 Modifier（替代目前借用的 `family.city.*`），
底层 stat 已存在：`economy.city.building.<部门>_output_factor`、`economy.city.good.<物资>.output_factor`、
`economy.city.output_factor`（全部产出）、`economy.city.trade_output_factor`、`economy.city.birth_factor`、
`economy.city.need.<需求>.consumption_factor`、`economy.city.resource.<资源>.regen_factor`。

## 2. 卡牌规则

**角色**（每张卡标一个主角色）：

| 角色 | 作用 | 典型稀有度 |
|---|---|---|
| 引擎 | 推高某项数值，让地块更容易满足标签 | 普通 |
| 收益 | 标签成立时给加成 | 普通 / 稀有 |
| 外溢 | 标签地块把加成扩散到邻格或 N 格内 | 稀有 |
| 叠层 | 事件或条件持续触发，层数随时间累积 | 稀有 / 传奇 |
| 计数 | 按地块数、卡数、信号数线性缩放 | 稀有 |
| 桥接 | 把一个体系的产物变成另一个体系的条件 | 普通 / 稀有 |
| ×区 | 独立乘算 | 传奇 |
| 规则 | 改写其他卡的范围、门槛、上限或计算方式 | 传奇 |

**数值基准**：

- 普通卡：命中条件时 +4%～+15%，或全国 +5%～+15%。
- 稀有卡：条件 +10%～+20%，外溢单源 +6%～+10%。
- 传奇卡：×1.10～×1.25，或改规则。
- 外溢卡一个来源平均命中约 6 格，所以单格 +10% 的价值约等于全国 +3%～+5%。
- 同一地块所有理念加成合计软上限 ×3，防止叠层和乘区失控。

**多来源规则**：每张外溢卡必须标明“叠加（附上限）”或“取最大”。

**升级**：L1 基础；L2 放大数值或范围；L3 追加一条子句。现有目录本来就允许每一级挂不同的效果程序，
所以“L3 加子句”不需要新机制。

**代价**：保留“每张卡至少一个负面项”的规则，但优先写成地块条件化代价。

## 3. 实现分级

| 级别 | 含义 | 卡数 |
|---|---|---|
| A 现成 | 只用全国 Modifier（含地形/地貌/物资/资源/气候/税项限定），改生成器即可 | 7 |
| B 地块基座 | 需要 X1 逐地块评估；之后只用已有 metric、选择器、叠层、按指标缩放 | 44 |
| C 小扩展 | B + 一个新 metric（X2/X3/X7/X8） | 21 |
| D 新机制 | 需要 X4/X5/X6 | 13 |

扩展清单：

| 编号 | 能力 | 说明 | 难度 |
|---|---|---|---|
| X1 | 逐地块评估 + 目标过滤 + 来源上限 | 当前地块类理念只锚定国家第一块自有地（`gdext/src/ideology_runtime.cpp:1294`）。改为对每块自有地按条件评估；选择器结果可按目标条件过滤；同一卡对同一目标可设来源上限。只在 Economy 提交新修订时重算脏地块。 | 中，**所有 B/C/D 卡的前提** |
| X2 | 计邻与连片规模 metric | “相邻满足条件的地块数”“所在连通块大小”。选择器已有 R1/R2/距离 N/同地形连通/同资源连通，缺的是把数量作为数值。 | 小～中 |
| X3 | 职业构成 metric | 某职业/职业类占地块人口比例，最大职业占比。 | 小 |
| X4 | 增量事件叠层 | 对比上一次已提交快照的差值，每次增加生成一层；每层独立到期。 | 中 |
| X5 | 规则改写 | 卡改卡：范围 +1、门槛降低、上限翻倍、条件替换、效果翻倍。编译期展开为参数覆盖表。 | 中～高 |
| X6 | 理念元机制 | 抽卡张数、重抽费用、理解度速度、复制相邻槽位。 | 中（都在理念运行时内部） |
| X7 | 计数 metric | 国家内某标签地块数、已装备卡/流派/协同数、已发现研究信号数。 | 小（X1 完成后基本免费） |
| X8 | 物资关系 metric | 周围不同主产物种类数、N 格内是否有上游原料产地。 | 小～中 |

性能注意：

- 选择器硬上限 32 格，所以“3 格内”（36 格）会按距离截断，需要在描述里写明“最多 32 格”。
- 现有 `max_effect_instances = 512` 不够“自有地块数 × 装备卡数”。X1 应直接产出按地块 CSR 的 Modifier，而不是每格一个 Effect 实例。

## 4. 体系总览

流派（农本/商贸/学识/动员/工造/调和）继续承担阶层态度和互斥组；新增的“体系”承担机制羁绊。
一张卡属于一个流派、一个主体系，可以带桥接标签。

| 体系 | 核心循环 | 卡数 | 覆盖时代 |
|---|---|---|---|
| Ⅰ 田垄 | 粮作成片 → 计邻 → 专精 ×区 → 扩大计邻范围 | 13 | 1–10 |
| Ⅱ 仓廪 | 农业支柱喂周围 → 人口增长 → 聚落/大邑阈值 → 城市乘区 | 8 | 0–8 |
| Ⅲ 矿冶 | 全国推铁煤 → 主产铁/矿业支柱 → 熔炉外溢 → 连片矿区 | 9 | 0–8 |
| Ⅳ 工坊 | 成链/建筑数缩放 → 上下游距离 → 工业 ×区 | 10 | 1–9 |
| Ⅴ 市易 | 多元 vs 专精的取舍 → 贸易 | 8 | 0–9 |
| Ⅵ 通衢 | 海岸/河谷/道路连通块 → 繁市 → 港口外溢 | 10 | 2–10 |
| Ⅶ 学识 | 书院：操纵理念系统本身；格物：知识地块外溢 | 14 | 0–10 |
| Ⅷ 劳作 | 职业占比阈值 → 新增人口叠层 | 4（+2 桥接） | 0–6 |
| Ⅸ 生灵 | 资源再生/富饶 → 气候自适应 → 富饶 ×区 | 9 | 0–10 |

建议的流派微调（可选，用于平衡动员只有 6 张的问题）：
`pit_dwelling`、`water_works`、`settle_and_farm`、`land_reclamation` 改为动员；`hydroelectric` 改为调和。
调整后约为：农本 15、商贸 18、学识 14、动员 10、工造 18、调和 10。

## 7. 示范构筑

**铁脉（矿冶 + 劳作 + 工坊桥接）**：盐铁专营推高铁矿 → 冶铁让邻格冶金 +10%～+30% →
煤田开发让矿业支柱 +20%，但农业 -10% 带来短缺 → 补常平仓 → 劳动立法随矿区扩张叠层 →
蒸汽动力在 4 块连片矿区内把前三张卡翻倍。

**稻浪（田垄 + 仓廪）**：治水营田 + 稻作形成「圩田」 → 垦荒令向外扩田 → 农政改革对专精稻田 ×1.10 →
共同体治理把余粮外溢给城镇 → 绿色革命把计邻扩到 2 格。

**百工市（市易 + 通衢 + 学识）**：馈赠交换和自由交换奖励混搭 → 市舶开港、远洋公司做港口繁市 →
集装箱港向工业外溢 → 百科全书按覆盖流派数整体增强。

这三套 build 刻意互相冲突：反垄断惩罚稻浪的高度专精；碳市场惩罚铁脉的工业支柱；
梯田和煤田开发争抢丘陵、山地。

# 第二部分：卡池扩充（v0.2）

## 10. 为什么要扩充

现有卡池按时代分布为 8 / 11 / 11 / 8 / 8 / 8 / 8 / 7 / 6 / 5 / 5。三选一抽卡每次展示 3 张，
而且有约三分之一的卡要求地图上存在特定资源、地貌或作物信号。
以石器时代为例，一张地图实际可抽的卡可能只有 5–6 张，两次抽卡就会开始重复。

扩充目标：

- 每个时代新增 6–11 张，使每个时代达到 16–17 张（见第 15 节）。
- 新卡尽量不加地图信号门槛（94 张中只有 3 张有），而是用地块条件筛选，保证任何地图都有足够多可抽的卡。
- 新卡重点接入家族、时代/科技、税收、地理水系、气候事件、阶层民意六类现有系统，
  让 build 不止依赖产出数字，还依赖玩家如何经营家族、定税、修运河、应对灾害和推进科技。

## 16. 卡池机制（X15）

卡数增加后，晚期卡池会被早期普通卡稀释。建议同时加入以下机制：

1. **时代距离衰减**：卡牌时代每落后当前时代 1 个，抽取权重 ×0.7（最低 ×0.2）。
   装备史馆 L3 时，旧学卡不再衰减。这样晚期抽卡主要出现当期卡，旧学 build 也有明确的开关。
2. **当期保底**：每次三选一中至少 1 张来自当前时代或前一时代。
3. **重复卡转为精进**：已拥有的卡仍可出现在三选一中，显示为「精进」。选择后该卡理解度 +4（约等于直接升一级）；
   已满级则返还本次抽卡费用的 50%。这相当于杀戮尖塔的卡牌升级，也能避免卡池枯竭。
4. **体系倾向**：已装备 ≥2 张某体系卡时，该体系其余卡的权重 +25%，帮助 build 成形。
5. **封存**：花费理念点把一张卡永久移出本局卡池，费用为当前抽卡费用的 1 倍。相当于杀戮尖塔的删卡。

这些都只改变理念运行时内部的抽卡 RNG 和权重，不影响其他系统。需要同步更新 PKID 存档中的抽卡状态（封存列表、精进计数）。

### 17.3 跨系统连锁示例

以下示例用来说明这些卡之间如何形成连锁收益，不是平衡结论。

**① 洪泛之子（天时 + 田垄 + 山河）**

阵容：河伯祭、淤田、治水营田、流域治理、稻作。

1. 三角洲稻田每年平均遭遇 2 次洪水。淤田叠到 5 层，农业 +20%；河伯祭的河赐常驻，再 +8%。
2. 治水营田让洪灾损失 -7%，流域治理在 10 个水利地块后再 -20%，洪水的负面被大幅抵消，但沃泥和河赐照常获得。
3. 稻作计邻 6 个稻田 +24%；淤田 L3 让层数 ≥4 的地块计为专精，又满足农政改革的 ×1.10。
4. 结果：同一块三角洲稻田在 +% 区约 +52%，再乘 ×1.10。玩家体验是"洪水一来，今年更丰收"。

**② 千年世家（宗族 + 工坊 + 矿冶）**

阵容：亲族火塘、宗祠、家族企业、工业世家、公司镇，搭配冶铁。

1. 亲族火塘提高家族所在地块出生率，家族人口更快增长，宗祠让名门地块 +6%，并加速名门家族在周边的扩张。
2. 家族企业让家产主导的工业地块 +12%；公司镇在家产雇员 ≥40% 时再 +10%。
3. 工业世家按家族人口给 ×1.20 上限，在名门地块再 ×1.05；冶铁让这些地块周围的冶金继续 +10%～+30%。
4. 玩家目标从"多建工厂"变成"扶持一个家族成为地区名门，并让它掌握工业"。

**③ 旧学复兴（纪元 + 学识）**

阵容：口传史诗、史馆、文艺复兴、改元，后期加算法治理。

1. 口传史诗让每次进入新时代时所有装备卡理解度 +1.0，加速升级。
2. 史馆让早 ≥2 个时代的卡等级强度 +15%；文艺复兴按覆盖时代数给知识 ×1.02/时代。
3. 阵容保留 5 个不同时代的卡时，知识 ×1.10；有了旧学新知协同，旧学卡按 2 个时代计，可达到 ×1.20 上限。
4. 这是唯一鼓励长期保留早期卡的路线，与"不断替换成新卡"的变法路线相反。

**④ 轻税之国 vs 太仓之国（度支两条路线）**

轻税路线：轻徭薄赋、摊丁入亩、补贴国家、免税特区。玩家主动把重点地块的税率调低，换取出生率和产出；
补贴国家把轻税地块变成 ×1.10，免税特区让零营业税地块周边工业贸易 +12%。

重税路线：包税、消费税制、太仓、银本位、财政审计、主权基金。玩家维持高税率积累国库，
国库比每 10% 降低死亡率和建造成本、增加贸易容量，最终用主权基金变成 ×1.10。

两条路线共用度支羁绊，但单卡收益明显对立，让税政策成为 build 的核心决策，而不是一次设定后不再调整。

**⑤ 人造天时（天时 + 学识 + 田垄）**

阵容：祈雨、汛期农法、寒暑历法、人工降雨、气象局。

1. 干旱地图上农业地块经常出现长旱期，祈雨在降雨后给甘霖 +12%。
2. 人工降雨把 ≥15 天的旱期强制变成降雨日，同时触发祈雨、汛期农法的沃泥层和寒暑历法 L3。
3. 气象局让剩余的真实灾害损失 -40%，每次预警命中还给科学研究叠层。
4. 结果：干旱地图从劣势变成"每 60 天固定收割一轮降雨 buff"的节奏型 build。

**⑥ 运河帝国（山河 + 通衢 + 市易）**

阵容：开渠、漕运、大运河、灌溉网、物流枢纽，搭配驿传。

1. 玩家利用现有运河建造系统修建运河，开渠让运河地块贸易 +10%、周边农业 +8%。
2. 运河网达到 8 格后，大运河让网内全部地块 ×1.10，并随网扩大到 ×1.20。
3. 物流枢纽让同时是繁市和运河/河畔的地块向周围 2 格 +6%；灌溉网给运河两侧 2 格抗旱。
4. 玩家目标变成"规划运河线路"，地图改造本身就是 build。

3. 不是「一格」：单锚点 + selector 展开（R1 = 7 格 / R2 = 19 格 / 同地形·同资源
   连通块 / 距离 N，硬上限 32 格）。

economy"，只校验声明层，因此「闭环已验证」的说法不成立。

**21.3 「max_effect_instances = 512 不够」的理由需要更正**

512 是**目录声明预算**（按效果行计），不是并发预算。并发上限是

所以逐地块铺开需要的不是「调大 512」，而是「按格聚合（CSR）+ 拆成两个预算」。

### 23.2 L0-2 的实际落地路径（含两处 §20 没写、不写就不成立的地方）

§20 把 L0-2 写成「公开化 + 归属」两件事，实现时发现还要多两件，否则闭环不成立：

1. **采样口**：`fill_family_behavior_metrics()` 是 private，新增公有门面
   `NativeEconomyRuntime::sample_effect_metrics(cell, metric_count, out, mask)`
   （`economy_runtime.h:7959`）——只取数，不碰 family 分支状态，可在意识形态
   日序里安全调用。
2. **发布归属**：`publish_family_effect_metrics()` 用的是**分支所在格**，而意识形态
   实例的目标是**选择器解析出来的格**。所以发布不能复用 family 那条路，改成在
   `reconcile_country_effect_activations()` 里按 `activation.ref.target_handle`
   逐**目标格**采样（`ideology_runtime.cpp:1511-1561`）。
3. **去重**：同一格可能被 9 张卡同时指向，按 `unordered_map<cell, values>` 缓存，
   一座格一天只扫一次建筑表。
4. **读回**：验收要能问「这个实例的 9 号指标现在是多少」。新增
   `EffectRuntime::instance_metric_pod()`（`effect_runtime.cpp:2704`），返回
   `present` 与 `value` 分开——「发布了 0」和「从未发布」必须可区分，否则测试只能
   验到「不是崩溃」。

`EffectActivation` 为此扩了两个字段（`ideology_runtime.h:255/259`）：`target_domain`
与 `metric_mask`。前者用来跳过 country 域（其 `target_handle` 是国家句柄，当格号读会
读到无关列），后者让「不引用任何指标的卡」完全免于采样——179 张里大多数如此。

**§20 表里没写、但不做就白做的一点**：`metric_mask == 0` 时完全不采样。风控意义在于
发布是按天、按格、按位做 `set_metric`，若对所有卡无条件采样，179 卡 × 3 级会把
`sample_effect_metrics` 变成日耗主项。

## 24. L0-1 落地记录：metric 选择集换型

### 24.1 原来卡在哪

`metric_mask` 是裸 `uint64_t`，于是 `effect_runtime.cpp` 在**编译期**就把
`arg0 >= 64` 判成 `effect_metric_mask_overflow`。这不是设计选择，是容器类型的
副作用：一个 256 位的选择需求被一个 64 位的整数决定了上限。

更糟的是它有两个隐蔽的连带问题：

1. `1ULL << metric` 在 `metric >= 64` 时是**未定义行为**，而三处消费点
   （`fill_family_behavior_metrics` 的 `requested()`、`publish_family_effect_metrics`
   的发布循环、`FAMILY_COMMIT_METRICS` 的常量构造）全都在做这个移位。
2. 掩码本身的语义有两态——「没请求任何指标」和「没有选择信息，全算」——却都用
   `UINT64_MAX` 和 `0` 混着表达，`full_metrics` 环境变量一开就把两者合并了。

### 24.2 换型范围（比预想小）

新类型 `MetricMask`（`metric_mask.h`）是 4 × `uint64_t` = 256 id 的定长值类型，
平凡可复制。实际改动只有 7 个文件：

| 文件 | 改动 |
|---|---|
| `metric_mask.h`（新） | `test/set/unset/count/word/is_none/is_all/has_id_at_or_above`、`all()`、`all_declared(n)`、`&= / & / ==` |
| `effect_runtime.h` | `FamilyEffectMetadataPod::metric_mask` 换型 |
| `effect_runtime.cpp` | 编译期守卫 `arg0 >= 64` → `!MetricMask::valid(arg0)`；`family_effect_metadata_pod` 用 `set()` 建掩码 |
| `economy_runtime.h` | `FamilyEffectBinding::metric_mask`、`_family_trait_behavior_metric_masks`、三个函数签名 + `static_assert(FAMILY_METRIC_COUNT <= MetricMask::CAPACITY)` |
| `economy_runtime.cpp` | `requested()` / 发布循环 / `FAMILY_COMMIT_METRICS` / 逐格缓存 |
| `economy_runtime_family_buff.cpp` / `economy_runtime_publish.cpp` / `economy_runtime_catalog.cpp` | 魔数位掩码改用 `MetricMask` + 枚举名 |
| `ideology_runtime.h/.cpp` | `EffectActivation::metric_mask` 换型，发布循环改 `test()` |

### 24.3 存档为什么不用迁移

`FamilyEffectBinding::visit_persisted` 看着像存档格式，其实**从未写入存档**：
`economy_runtime_persistence.cpp` 只在 reset 时 `clear()` 它，没有任何
writer/reader 走它。它唯一的消费者是 `EconomyVariableRecordCodec`，那是 **worker
变更日志**的列编码器，同进程内生产、同进程内消费，不需要跨版本兼容。

`FamilyEffectMetadataPod` 同理——它是 `family_effect_metadata_pod()` 的返回值，
进程内按值传递，不进任何 wire。worker 侧 POD 的指标上限是
`RUNTIME_EFFECT_POD_MAX_METRICS = 65536`，本来就不是 64，不需要动。

**所以这次换型没有存档格式变更。**

### 24.4 新的上限是「表长」，并且有契约守着

换型只解决了「装不下」。真正的上限变成了
`NativeEconomyRuntime::FAMILY_METRIC_COUNT`（当前 50）——那是**经济侧能算多少**，
而 `effect_domain_catalog.gd:metric_keys`（也是 50）是**id 代表什么**。

两者一旦不等，会出现和 L0-2 修掉的那类问题一模一样的**静默失效**：目录声明了
第 51 个 id、某张卡条件引用它，编译通过、实例建出来、条件永远假，全链路没有任何
报错。所以在 `DCWorldExt::configure_effects` 里加了硬契约：

```
metric_keys.size() > FAMILY_METRIC_COUNT
  → {"ok": false, "reason": "effect_metric_count_exceeds_economy",
     "declared_metrics": N, "computed_metrics": 50}
```

放在这里而不是 `configure_economy`，因为声明数量在这一刻才可知，而
`FAMILY_METRIC_COUNT` 是编译期常量，不需要经济实例存在。

**这条契约同时就是扩容的操作规范**：加指标必须三处同改——`FamilyEffectMetricId`
枚举、`FAMILY_METRIC_COUNT`、`metric_keys`。漏一处，`configure_effects` 直接失败。

### 24.5 还没做的：表本身还是 50

L0-1 交付的是**机制**，不是**指标**。今天 `MetricMask` 能寻址 256 个 id，但目录
declare 超过 50 个就会被契约拒绝，因为经济侧只算 50 个。

要把 id 真正用到 64 以上，必须真正实现那些指标的读数（`fill_family_behavior_metrics`
里加分支），那是 X9–X14 的内容工作。所以验收测试分两层：

- **机制层**（已交付）：`metric_mask_tests.cpp` 9 组断言，覆盖 63/64、127/128、
  191/192 三个字边界、越界忽略、`all()` vs 空、`all_declared` 截断、
  `has_id_at_or_above` 与集合运算。这是今天唯一能直接断言 id 64..255 的地方。
- **契约层**（已交付）：`metric_mask_capacity_test.gd` 12 checks，证明恰好 50 个
  声明可通过（条件落在最后一个 id 49 上）、51 个被拒绝且理由正确。

### 24.6 顺带清掉的技术债

- `economy_runtime_publish.cpp` 的 `(1ULL << 7U) | (1ULL << 8U) | ...` 魔数位掩码
  改成 `MetricMask` + 枚举名（`CELL_RESOURCE_SHORTAGE_Q16` 等）。核对过枚举值，
  7/8/9/11/14 与原魔数完全一致，行为不变。
- `economy_runtime_family_buff.cpp` 的四处 `uint64_t{1} << METRIC_*` 同样改掉。
- `economy_runtime.cpp:16139` 的 `industry_mask`（id 15..21）从
  `((1<<22)-1) ^ ((1<<15)-1)` 的算术技巧改成显式循环 `set()`。

### 24.7 一处**未动**的同名概念，别混淆

`economy_runtime_events.cpp` 里还有一个 `thread_local std::vector<uint32_t>
type_metric_mask`，那是**建筑开发指标**的选择集（`_development_metric_types`，
按建筑类型缓存 `metric_matches_group()` 的结果），与 `FamilyEffectMetricId` 是
两套独立 id 空间，上限 32 也来自它自己的表长。它不在 L0-1 范围内，但如果开发指标
表将来超过 32 条，那里会以同样的方式静默截断——届时照 `MetricMask` 的做法处理。

## 25. L1-4a 落地记录：国家领土索引 + `SELECTOR_OWN_TERRITORY`

### 25.1 勘察结论：CSR 早就存在，缺的只是「接过来」

开工前的判断是「L1-4 要先决定是否新建每国领土 CSR」。实测否掉了这个前提：

| 事实 | 位置 |
|---|---|
| `RuntimeCountryPodSnapshot` **已有** `territory_offsets` / `territory_cells` / `territory_count` | `runtime_country_pod.h` |
| 构建函数存在，就是一遍计数排序 | `country_core_rebuild_territory_csr()`，`country_core_apply.cpp:846` |
| 权威侧也能转出 | `RuntimeCountryPodAuthority::rebuild_territory_csr()`，`runtime_country_pod.cpp:1211` |
| 但 `EconomySnapshot` **不携带** CSR，只带 `cell_country_slot` | `country_runtime.h:158` 结构体字段清单 |
| `capture_country_epoch` 把 `cell_country_slot` move 走后，快照其余部分就丢了 | `economy_runtime.cpp:4759` 前后 |

所以这不是架构选择题。正确做法是**在 `_epoch_cell_country` 落地的那一行顺手做一遍
计数排序**：与已有列同源同刻（不会出现「锚点说 owned、CSR 说没 owned」的矛盾），
不需要改 `EconomySnapshot` 这个跨域契约，也不需要赌 country pod 的 CSR 时机
（`rebuild_territory_csr` 目前**零调用点**，pod 内部只在 bootstrap 时建一次）。

### 25.2 改了什么

**新列 + 构建**（`economy_runtime.h` / `economy_runtime_family_buff.cpp:886`）

```cpp
std::vector<int32_t> _epoch_country_cell_offsets;  // countries + 1
std::vector<int32_t> _epoch_country_cells;         // 按格号升序的所有自有格
```

`rebuild_country_territory_index()` 三趟 O(cells)：计数 → 前缀和 → 升序散射。
**升序散射是语义的一部分**：它让每个国家的切片天然升序，于是 cap 永远保留最小格号，
选择器才可复现。无主格（槽位 < 0）不进 CSR。

**接入点**：`capture_country_epoch`（`economy_runtime.cpp:4768`），紧跟
`_epoch_country_count` 赋值之后——晚一行 `country_count` 还是旧值，早一行
`_epoch_cell_country` 还是空的。重置路径（原 24349 行附近）同步清空两列。

**新访问器**

| 接口 | 语义 |
|---|---|
| `country_cell_count(slot)` | 该国当前 epoch 拥有的格数，0 表示没有或索引未就绪 |
| `country_cell_at(slot, index)` | 第 index 个自有格（升序），越界 -1 |
| `country_territory_index_ready()` | `private`，判定索引与 `_epoch_country_count` 自洽（切片表长度、`offsets.back() == cells.size()`） |

三者都有**线性回退**：索引未就绪时按 `_epoch_cell_country` 扫。这条不是保险丝而是
测试支柱——自检里专门断言「清掉索引前后结果逐格一致」，否则手工 fixture 与真实 epoch
会走出两套行为。

**`country_anchor_cell` 从 O(cells) 变 O(1)**。原实现对每次调用扫全图，而它在
`resolve_effect_targets` 里是**每个国家 × 每条效果行 × 每次 reconcile** 都调一次。
索引就绪时直接读 `offsets[slot]` 的首项——散射顺序保证它就是最小格号，与原返回值
逐字节相同。

**新选择器 `SELECTOR_OWN_TERRITORY = 12`**（`effect_runtime.h:140`）

- `param0` = cap（缺省 `SELECTOR_MAX_CELLS`，不是 8——这个 kind 的设计意图就是「能塞多少塞多少」）
- `param1` = 谓词 id，与 `SELECTOR_PREDICATE_ANY_CELL` 同一套编号（0 = 不筛，1 有河，2 是水，3 非水）
- 语义：**先按领土枚举，再按谓词筛**；`SELECTOR_PREDICATE_ANY_CELL` 是**先筛全图**，两者只差这一步
- 谓词无命中时返回空，**不回退到锚点**。「只在满足条件的地块生效」的卡如果因为没命中就把效果
  塞到不满足条件的锚点上，正是 L1-5 要防的那个 bug
- 源格无主（槽位 -1）时保持「解析到锚点」的旧契约，这是唯一还返回源格的路径
- 该分支**放在建筑快照守卫之前**：领土是所有权问题，不能在「epoch 已捕获、建筑列还没刷新」
  的窗口里静默消失

### 25.3 顺带修掉三处「N 个实例仍指同一个格」

`target_handle` 的按格覆盖原来只对 kind 6/7 生效，kind 8..11 会展开成 N 个实例但
`target_handle` 全部保留 `base_target_handle`（锚点）——「同格 N 份」而不是「N 个格各一份」。

改为 `kind >= SELECTOR_NEIGHBORS_R1` 的三处：

| 位置 | 场景 |

| `economy_runtime.cpp:17729` | reconcile 的 apply 路径 |
| `economy_runtime.cpp:17890` | reconcile 的 binding 路径 |
| `economy_runtime_family_buff.cpp:674` | `grant_family_effect_to_branches` |

安全性来自实测而非推断：`data/economy/family_official_buffs.json` 的 48 行 family 效果
只声明了 kind **0 / 2 / 3 / 5 / 6**，没有任何 8..11 的行。所以这次放宽对既有 family
数字**完全无影响**，只是让新 kind 12 在 family 路径上不会一上来就错。

### 25.5 还没做的：真正的「标签反向索引」，以及它为什么不能顺手做

现在 `SELECTOR_OWN_TERRITORY` 只有 3 个占位谓词。第 1 节标签词典的 15 类里，13 类可以直接
写成「metric + 比较 + 阈值」（专精/多元/成链/繁市/边地/失业/短缺/富饶/枯竭/地貌/降雨日/
主产 X/富藏 R），但**粮作**（主产物 ∈ 小麦/稻米/玉米/马铃薯/谷物）需要**集合成员**语义，
而这不是阈值能表达的。三条硬约束决定了 L1-4b 的形状：

1. **`target_selector_param[2]` 不能简单扩成 4。** catalog 侧是
   `target_selector_params` 的 `count * 2` 扁平数组
   （`effect_runtime.cpp:750 / 789 / 898`），改成 4 会连带要求生成器、
   形状校验、`configure` 比对（1201-1202）和签名哈希（1258-1259）一起改，
   属于**破坏性格式变更**。不破坏旧 catalog 的路径是**并列新表**——
   `tag_*` 系列数组缺席即等于「无标签」，旧 catalog 照常通过。
2. **标签求值必须发生在 economy 侧。** 求值点是 `collect_effect_target_cells`，
   而指标采样入口是 `sample_effect_metrics()`（L0-2 交付的单格门）。
   若在查询期逐格采样，成本是 `领土格数 × 标签行数`，并且**每次 reconcile 重付一次**。
3. **所以每格位图不是优化，是成本前置。** 必须每 epoch 预算一次、按位查，才能在
   reconcile 里用得起。这也正是「反向索引」这个名字的真正含义——不是「有个索引」，
   而是「查询期不做指标采样」。

据此，L1-4b 的待定形状是：`tag_offsets` + `tag_metric_ids` + `tag_metric_ops` +
`tag_metric_thresholds`（一个 tag = 行段内 **OR**），配一张
`cells × ceil(tag_count/64)` 的 `uint64_t` 位图，在 `capture_country_epoch` 之后
按 `MetricMask` 收窄采样集合后重建。粮作的集合成员语义走 `op = IN_GROUP`，
前置条件是物资分组进 catalog（属于 L5-14「编译期符号解析」的一部分）。

### 25.6 一处**刻意没改**：`SELECTOR_PREDICATE_ANY_CELL` 的全图语义

它是**全图扫描**（`economy_runtime_family_buff.cpp` 的 predicate 早退分支），
对「本国某类地块」这种卡会命中敌国领地。本次没有收窄，原因有两条：

- 既有内容与单元测试都依赖全图语义（自检的 `selector_predicate_river_hits` 一直是
  「整张图上有河的行全部命中」，§25.4 新增的并排对照还把它在两国网格上钉成 6 格）；
- 收窄会静默改变已有 selector 的命中集，与 L0-1 换型时「不动既有数字」的原则冲突。

需要国别的卡一律改用 `SELECTOR_OWN_TERRITORY`。真正该做的是给 `PREDICATE_ANY_CELL`
加一个显式的 scope 参数，那属于 L1-5（选择器后的条件过滤）的形状，与标签位图一起做更合适。
