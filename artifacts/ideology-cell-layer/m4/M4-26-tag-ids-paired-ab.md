# M4-26 tag_ids 的配对 A/B：1.29× 真实收益，并找到下一个瓶颈

| 项目 | 内容 |
|---|---|
| 里程碑 | [M4](../22-cell-program-cap-removal-plan-v3.md) §15.6 |
| 日期 | 2026-10-28，Asia/Hong_Kong |
| 结果 | **配对差中位数 +3.20 ms（1.29×）**，12 对中 9 对为正 |
| 结论 | 收益真实但远小于 6.2× match 缩减——**瓶颈在别处** |

## 1. 为什么必须做配对测量

前两次尝试都不成立：

| 方法 | 结果 | 问题 |
|---|---|---|
| 单次对比 | 16.49 vs 26.62（1.61×） | 单次，不可信 |
| 12 跑交替分组 | 1.08× | 组间漂移全算进差异 |

**做成配对**：每次运行 narrowed → forced **紧邻**，各取 `tag_build_ms`，算**配对差**。这样漂移同时作用于两臂。

## 2. 配对结果（12 对，同一二进制）

```
narrowed : 24.65, 24.18, 23.85, 18.94, 16.32, 17.34, 22.65,  7.28,  7.31, 11.26,  7.28,  7.64
forced   : 22.43, 23.04, 18.72, 26.10, 23.91, 27.91, 26.16,  9.60, 14.21, 14.15, 14.50,  8.49
diff     : -2.22, -1.14, -5.13,  7.15,  7.59, 10.56,  3.51,  2.32,  6.90,  2.89,  7.22,  0.85
```

| 指标 | 值 |
|---|---|
| 12 对中为正 | **9 对** |
| **配对差中位数** | **+3.20 ms** |
| 中位数对比 | 17.34 vs 22.43 ms = **1.29×** |

**A/B 开关本身已验证有效**：`active=48` vs `active=296`、`consumed=48` vs `consumed=0`。

## 3. 关键发现：match 缩减 6.2×，墙钟只有 1.29×

```
match 次数：473,600 → 76,800   （6.2× 减少）
墙钟      ：22.43 ms → 17.34 ms（1.29× 改善）
```

**说明 tag-match 循环不是主要成本。**

`rebuild_epoch_tag_snapshot` 的循环是：

```cpp
for (cell = 0; cell < cells; ++cell) {
    sample_effect_metrics(cell, metric_count, values.data(), mask);   // ← 每格一次
    for (tag : active_tags) { matches(...) }
}
```

`sample_effect_metrics` **每格调用一次，与 tag 数无关**。当 tag 从 296 降到 48，它一点没变。

**下一个瓶颈是逐格 metric 采样，不是 tag 匹配。**

## 4. 判定

| 项 | 结论 |
|---|---|
| `tag_ids` 协议 | **正确且有收益**（1.29×，9/12 一致）|
| match 数 6.2× 缩减 | 确定（计数）|
| 墙钟 6.2× 缩减 | **不存在**；实际 1.29× |
| per-tag changed words 的价值 | **需要重新评估**——即使做到 0 match，最多再省 ~5 ms |

## 5. 对 M4 计划的影响

方案 §15.6 要求「per-tag changed words，缩小来源组失效范围」。

**现在有量化依据**：tag 匹配在 1600 格下约占 5 ms / 22 ms（23%）。
即使增量更新把它降到 0，收益上限也只有 ~23%。

**而 `sample_effect_metrics` 每格一次的开销占大头。** 若要把 `tag_build_ms` 降一个数量级，
应该优化采样（例如只采 `mask` 内的 metric、或按 cell 分片），而不是 tag 侧。
