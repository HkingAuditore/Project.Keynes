# polytech-tree 实际数据参考审阅

审阅对象：`secwind7/polytech-tree` 的 `data/techs.json`、`data/eras.json`、`data/categories.json` 和 `data/core-ids.json`。

## 数据规模与分层

- 3,862 个科技节点。
- 11 个时代：从 Prehistory、Neolithic、Bronze Age、Antiquity、Middle Ages、Renaissance，延伸到 Industrial、Second Industrial、Atomic and Electronic、Information、Intelligent。
- 22 个领域，包含数学、逻辑、算法、物理、生命医学、制造、交通、能源、农业、材料、建筑、经济、治理、军事、教育、信息媒体和太空等。
- 重要度为 1–5；1 是基石，5 是长尾补充。它同时影响视觉尺寸和多面体复杂度，也提供内容优先级。

## 拓扑规则

### `prereqs` 与 `related` 分离

每个节点都有独立的 `prereqs` 和 `related`：

- `prereqs` 表示必须先有的知识；
- `related` 表示相关应用、近邻技术、替代方向或后续提示，不会把整张图压成一条硬门槛链。

这一区分是本项目当前最需要吸收的设计。Project Keynes 的硬前置应只保留不可替代知识，跨产业关联应更多进入 application/feedback 边，而不是继续增加 `hard_prerequisite_ids`。

### 真实能力链示例

早期数据不是按“农业科技 I/II/III”填表，而是从具体能力展开：

```text
火 -> 火塘 -> 烹饪
石器 -> 装柄术 -> 复合工具
石器 -> 木工 -> 木筏/船
刮削器 -> 皮革 -> 缝制衣物
食物储存 -> 谷物储藏 -> 食物保存
```

这些节点的名称、前置和相关技术都对应可理解的物质能力，且 `related` 会把同一能力连接到多个应用方向。

中后期则出现跨领域汇合：

```text
数学/几何 -> 微积分 -> 力学/热力学 -> 电磁学 -> 电子计算 -> 网络/AI
文字/纸张/印刷 -> 知识传播 -> 科学制度 -> 工业研究
农业/冶金/能源/运输 -> 工业生产系统
```

### 实测拓扑指标

- 硬前置边：4,962。
- 跨时代硬前置边：2,839。
- 同时代硬前置边：2,123。
- 有硬前置的节点：3,214；平均硬前置数：1.28。
- 根节点：648；叶节点：2,152。
- 最长硬前置深度：16。
- `related` 平均约 2.30 条/节点，绝大多数节点都有相关技术连接。

这说明它不是“所有节点都必须串成一条完整主线”，而是用少量硬前置保持因果，再用大量 related 边形成可探索的技术邻域。

## 对 Project Keynes 的具体采用项

### 直接采用

1. 在设计数据中明确区分：
   - `hard`：不可替代知识；
   - `alternative`：不同证据或路线满足同一研究入口；
   - `application`/`feedback`：相关能力和产业交汇，不阻塞研究完成。
2. 为核心节点增加 `importance_tier`，用于审计优先级和 UI 信息密度，不改变研究成本或运行时数值。
3. 用具体能力链重写名称、效果和后继关系，避免“泛化升级科技”连续占位。
4. 让一个节点可以有多个相关后继，但只保留少数硬前置。
5. 对跨领域汇合节点记录来源领域，而不是把所有来源都变成硬前置。

### 不直接采用

- 不导入 3,862 个百科节点；Project Keynes 的节点必须有真实经济内容、研究信号或现有 runtime consumer。
- 不把 `related` 自动转换为研究前置。
- 不照搬现实年份作为研究可用日；Project Keynes 仍由时代、发现信号、路线和国家研究状态共同决定。
- 不使用其 3D 多面体展示替代现有迷雾、可研究集合和应用交汇 UI。

## Wave 1 需要调整的地方

Wave 1 的关系链现在应被视为“主干 + 相关能力边”的组合，而不是全部硬前置：

- 主干链保留少数不可替代的核心前置；
- 农业、水利、冶金、贸易、公共卫生和计算链增加 `related/application` 关系；
- `tech.networked_computing` 与 `tech.machine_learning` 的材料和供应链依赖先降为应用/反馈候选，再通过闭包审计决定是否保留硬前置；
- 识别、采集、加工节点继续保留，但必须有明确的能力后继或应用绑定；
- 长尾节点通过 `importance_tier` 标记为低优先级，而不是把它们全部当成同等重要的研究选择。
