# 开发流程 / 并行协作 / 事后检查

## 1. 开发前

1. 读当前要改的文件、它的 view model 与主题来源。禁止凭文件名或旧文档臆测。
2. 写出玩家打开这个界面要回答的 2–3 个决策问题（用玩家语言）。据此决定字段顺序、首屏内容与哪些数据该下钻。
3. 查 `references/antipatterns.md` 对应类别，确认本次不要复发的真实反例。
4. 确认数据流与换算点：`模拟数据 → view model → UI 组件`，UI 只读不写模拟；内部缩放因子只在展示层换算。
5. 确认风格基准（剪纸撕纸手绘）与可用的 `PK*` 主题变体 / 纸片资产。

## 2. 开发中

- 先接既有资产与组件，再考虑新造；先删无用信息，再考虑补充。
- 每个数值标参照；每个图形自带量程；空态整节不渲染；短标签 / 数值关 autowrap。
- 只改本次范围内的文件。禁止顺手动数据结构、字段名、信号、存档格式、C++ / GDExtension、tests 断言、`project.godot`。
- 删除文案时连同承载它的空容器 / section title / `custom_minimum_size` 一起删。
- 修改后的文案必须是玩家语言，不能用新套话替换旧假数据（见下方事故）。
- 拿不准的改动跳过并登记，不要强行改。

## 3. 多 agent 并行改同一仓库

**按文件所有权分区，不按问题簇分区**。两个 agent 写同一个文件必然互相覆盖。

1. 用 union-find 把「共享同一文件的条目」绑成连通分量，同一分量不拆分。
2. 按条目数贪心负载均衡到 N 个桶，每桶输出一份工单，含**独占文件清单**与条目全文（ID / 位置 / 原文证据 / 修法 / 来源）。
3. 验算任意两工单的文件集合交集为空，把证明写进 manifest。
4. 改前把待改文件按原目录结构备份，可整体回退。
5. 工单写死纪律：只改独占文件；改前核对原文证据仍存在（文件可能已被别的会话改过，对不上就跳过）；拿不准跳过并记录。
6. **并行期间禁止各 agent 运行 Godot / 跑测试 / 写 `.godot/`**（多进程会互抢），统一由主会话在全部改完后验证。
7. 按覆盖率收敛判停，不按墙钟时间挂机；以「整类未扫 + 交叉复核深度」判收敛。

用 `scripts/build_workorders.py` 生成工单；2026-11-05 实测 149 条 / 96 文件 → 85 个连通分量 → 8 桶，交集为空。

## 4. 事后检查（必做，顺序执行）

### 4.1 全项目脚本编译
```bash
godot_console --headless --path <ROOT> --editor --quit > compile.log 2>&1
grep -E 'Parse Error|Failed to load script|SCRIPT ERROR' compile.log
```
必须为 **0**。这一步能抓出并行改动中最常见的缩进 / 括号事故。真实例：删「暂无投入」文案时把 `technology_workspace.gd:1119` 的 `elif` 缩进改坏，报 `Expected statement, found "elif" instead`。

### 4.2 领域测试
```bash
godot_console --headless --path <ROOT> -s res://tests/military/military_roster_gate_test.gd
```
按改动域选对应测试，至少跑一条能覆盖该数据链的。

### 4.3 带渲染的截图回归
```bash
godot_console --path <ROOT> --resolution 1600x900 -s <probe>.gd
```
**不能加 `--headless`**：headless 用 dummy 渲染驱动，`get_viewport().get_texture().get_image()` 拿不到画面；且默认 `run/main_scene` 是 `main_menu.tscn`，游戏内界面不会实例化，必须写探针主动挂载目标面板。项目已有 harness 范例：`tests/military/military_workspace_screenshot.gd`、`tests/qa/*_screenshot_qa.gd`。

探针要点：`extends SceneTree` → `_init()` 里 `call_deferred("_run")` → 加背景 → 实例化目标场景 → `set_model(...)` → 等 `RenderingServer.frame_post_draw` → `root.get_texture().get_image().save_png(path)` → `quit()`。多分辨率与快进状态都要截。

### 4.4 新增行倒退检查
```bash
git diff -U0 -- <改动文件> | grep '^+'
```
逐行看新增文案，词表：`暂无`、`读取中`、`尚未就绪`、`待结算`、`不计`、`无需`、`—`、`…`、写死假读数、示例数据。**这一步比 agent 自检有用**：2026-11-05 并行修复中，多个 agent 把「天气：晴朗」改成「天气：—」、新增 8 处「读取中…」、「暂无数据」「暂无读数」，属于用新套话替换旧假数据，直接违反内容准则。

### 4.5 反模式扫描
```bash
PYTHONPATH= python scripts/audit_ui.py --root <ROOT> --out <OUT>
```
输出 `pattern_hits.csv` 与 `pattern_stats.md`。**机械命中不等于问题数**：2026-11-05 实测 4240 条命中、整体误报率 61.2%，确认根因簇只有 46。必须逐条人工复核并区分「真问题 / 必要信息 / 误报」。

### 4.6 数字复核
不同口径的数字不可直接比较。实测 v2 的 `add_theme_*_override` 951 / separation 652 / 硬编码坐标 401 / 布尔 visible 548 / 硬编码色 918，与另一轮统计的 933 / 614 / 1261 / 741 / 379 **五项全部不等**，差异来自正则口径、是否含 `.tscn` / 注释 / ext 文件。报数时必须写明口径与分母。

### 4.7 覆盖率核验
- 生成磁盘全量清单（`find`，不要用 `git ls-files`——曾漏列 2 个 `.gd` 且误收 tools 场景）。
- 算 0 命中文件、单报告弱覆盖文件、被 ≥2 视角复核文件。
- 对 0 命中与弱覆盖文件逐文件补审，给出核对表；「无问题」也要写并附依据。
- 桩场景（≤10 行）要追踪**谁实例化了它**、注入方有没有补状态 / 溢出 / 换行策略。

## 5. 验收清单（玩家视角）

- [ ] 新玩家 3 秒内能说出「这是什么、好在哪、有什么风险、能做什么」？
- [ ] 策略玩家一次点击 / 一个 tab 能下钻到数值成因？
- [ ] 地图仍是视觉主导，UI chrome 没有挤压它？
- [ ] 界面读起来是剪纸撕纸手绘的档案，不是调试面板或通用仪表盘？
- [ ] 数据可追溯到既有模拟来源，UI 没有自己造数？
- [ ] 高速模拟 / 快进时界面不闪、不跳、按钮始终可点？
- [ ] 图标一致、有授权来源，不是 Unicode 占位？
- [ ] 按钮六种状态齐全、标签可读？
- [ ] 1280×720 / 21:9 / 移动档无横向裁切？
- [ ] 关掉动效后界面仍完整可用？

## 6. 已知静态扫描盲区（不要假装查透了）

- **运行时**：`--headless` 只加载 `main_menu.tscn`，界面级表现无一条运行时复现；需探针或真机。
- **玩家侧因果**：字段顺序混乱是否真的造成误读，需要任务理解度测试 / 逐面板截图 / A/B 反例，静态证据只能证明「顺序不按决策」。
- **真机触控、长中文溢出实测、色盲安全与对比度量化**：只做静态推算。
- **近重复与疑似条目**：标题相似度 ≥0.55 的对子要人工裁定，不要自动合并。

## 7. 交付与回退

- 未提交 commit 前，用备份目录按原路径覆盖即可回退；**不要用 `git checkout .`**，会波及并行会话对 C++ / data / tests / docs 的改动。
- 报告里分层写清：机械命中数 / 确认问题数 / 行号级可开工条目 / 需设计决策条目，禁止硬加总混淆口径。
- 「细化」（旧结论补了具体行号）不算新增问题，不虚增战果。
