# 环境驱动的科技路线差异化

> 实现状态（2026-08）：本轮网状科技树已经落地。当前权威目录为 360 项科技、11 个时代、
> 4 个领域；不存在全球统一开局科技，22 个零成本原始处理节点只能由区域开局求解器按当地
> 证据授予。每时代固定 16 个候选、任意完成 5 个后才可研究里程碑。下文仍保留的早期设计
> 示例只用于解释运行时边界；凡出现“180 项”“8 选 3”或“玉米栽培直接开放农场”的描述，
> 均以本节及 `technology-tree-runtime.md` 的当前契约为准。

## 当前网状目录契约

- 节点角色为 `identification`、`handling`、`production_system`、`power_scale`、
  `institution`、`applied_method` 和 `milestone`；路线、泳道、里程碑候选与开局能力是静态元数据。
- 目录在编译时把基础表与产业网表做稳定拓扑排序；里程碑候选边只参与排序和 16 选 5 计数，
  不会被错误编译为 16 项全部必需的普通前置。
- 普通科技直接内容绑定最多 4 项，其中建筑/生产方式最多 2 项；里程碑的直接内容绑定必须为 0。
- `BuildingProfile.technology_tags` 是直接应用科技的 ANY 门槛；
  `required_technology_tags` 是对象、环境体系、动力和制度等全部必须满足的 ALL 支撑轴。
- 发现条件只揭示和允许研究辨识节点。玉米、麦、稻、块茎、棉、亚麻、香料、橡胶、煤、
  金、银、黏土、自然铜、锡等均不再由地图信号直接开放成熟生产建筑。
- 六个旧的 `*_cultivation` 作物整包节点已退出可执行目录。玉米主干为辨识→野生采集→留种→
  繁育，再与园圃、刀耕火种、雨养田或洪泛退水体系交汇；水田稻作直接以前置的畦埂和水位
  控制为基础；高地块茎以前置垄作和防霜保存为基础。
- 黏土链为辨识→调泥→手制低温陶→陶器容器体系/窑烧→烧砖；铜锡链为自然铜辨识→冷锤→
  退火→铜矿焙烧→木炭坩埚炼铜，与锡矿辨识/真实贸易接触交汇后才进入铜锡配比与铸造。
- 罐藏与冷链、矿物/作物/水文遥感、发电机/电动机/电网、通用动力与行业应用均保持独立。

## 当前开局与实践证据

开局求解器扫描首都和一环的生物、资源、地貌与气候信号，在海岸、洪泛地、寒冷高地、
热带森林、干旱高地和温带路线中选择真实可运行的食物、衣物、建材、贵金属与知识建筑。
只补一个最合理的金或银点以及闭包证明必需的至多一个非贵金属资源；预建建筑不含庄园、
成熟矿井或工厂。食物缓冲为当地食物建筑产物的 15 日量，不再发放 60 日通用加工食品。

跨国实际交付玉米、小麦、稻、薯、棉、亚麻/韧皮、香料、乳胶或锡样本时，Economy 才发布
`technology contact` 事实；Trigger 通过独立的 `contact.discover` Effect 模板写入永久
`contact.*` 信号。有效生产日按就业率和利用率折算；基础处理、环境体系、动力/矿井/工业
组织分别以约 120、240、360 个有效日形成 `breakthrough.*`，空建筑不能刷取突破。

本文定义 Project.Keynes 科技内容的设计方向：让国家的地理、气候、植被、资源、人口、
建筑、社会组织和历史事件改变“可发现、可研究、可应用”的路线，同时充分复用现有
`ResearchSignalCatalog`、`NativeCountryRuntime`、`TriggerRuntime`、`EffectRuntime`、
`ModifierRuntime` 和 `NativeEconomyRuntime`。

本文是内容与运行时之间的设计契约，不引入独立的 `TechnologyRuntime`。当前科技权威仍是
`TechnologyCatalog`，国家研究状态仍由 `NativeCountryRuntime` 持有。

## 设计目标

科技树需要满足以下目标：

- 同一时代允许多个合理入口，不把所有国家压成一条欧洲式线性顺序。
- 环境和地理先改变证据与机会，再改变路线，不用随机数直接给国家发科技。
- 发现、理解、研究、应用、规模化和传播是不同阶段。
- 科技完成后必须产生可观察的经济、建筑、职业、资源或制度差异。
- 选择应有代价和机会成本；一条路线强，不代表它在所有地图都强。
- 低概率或稀有发现可以形成特色，不得成为所有国家必经的时代门槛。
- 所有跨域结果都经过现有 Effect 事务、域适配器和 ACK 边界。

## 现有机制与边界

当前落地目录是 180 个科技、11 个时代、4 个研究领域。每个时代的里程碑要求八个候选中的
任意三个，且至少四个候选不受稀有资源或特殊地貌硬锁；正常节点要求显式直接前置。`TechnologyCatalog` 已经把
`TECH_COMPLETED`、`SIGNAL_PRESENT`、`SIGNAL_COUNT`、`ALL_OF`、`ANY_OF`、`AT_LEAST`
和 `NOT` 编译成 Native postfix IR。

现有可复用能力：

| 能力 | 当前权威 | 用途 |
| --- | --- | --- |
| 地图、生物、资源、地貌证据 | `MapGenerator` / `MapData` / `ResearchSignalCatalog` | 生成每格可观察事实 |
| 国家观察结果 | `NativeCountryRuntime` | 保存国家本地、永久、可审计的信号 bitset 与证据计数 |
| 事件事实与游标 | `GameplayEventBus` | 接收发现、天气、经济提交和未来的历史事件 |
| 累计、窗口、序列、去重 | `TriggerRuntime` | 把短期事实转成有意义的突破门槛 |
| 计划、跨域事务、幂等、ACK | `EffectRuntime` | 把科技或突破结果提交给 Country、Modifier、Economy、Gameplay |
| 永久数值效果 | `ModifierRuntime` | 研究效率、具体物资产出、建筑方法、贸易或建设因子 |
| 物资、建筑、职业和资源生产 | `NativeEconomyRuntime` | 执行真实市场、就业、生产、资源扣减和守恒 |

当前限制也必须显式保留：

- `COUNTRY_FLAG`、`COUNTRY_STAT`、`BUILDING_COUNT`、`EVENT_OCCURRED`、`SEQUENCE` 和
  `WITHIN_DAYS` 仍是声明面，不能在 Native 中当作永真条件。
- 当前经济是国内贸易；跨国贸易、外交和国际知识传播不属于本设计的第一阶段。
- 当前每个非开局科技都有唯一 Effect recipe，至少包含永久 `technology.modifier` 与
  `technology.adopted`；更复杂结果继续把命令编译进同一个 Effect 事务，不能绕过 Effect。
- 自然资源储量是真实存在的 DataCore 状态；`discovery_technology_tags` 只控制发现可见性，
  采集能力仍由建筑的 `technology_tags` 控制。

## 四阶段知识模型

科技内容按以下链条设计：

```text
物理事实
  -> 国家观察证据
  -> 可解释的知识突破
  -> 研究机会与队列
  -> Effect 原子化完成
  -> 具体产业和制度应用
  -> 规模化、适应和后续突破
```

### 物理事实

物理事实由地图、气候、植被、地貌、资源和天气系统产生。它们不属于科技状态，不能因为
科技改变而凭空出现。示例包括：

- 某格有河流、河口、火山、高原或可耕地。
- 某格属于适合玉米、小麦、马匹或块根作物的生态区域。
- 某国领土内存在煤炭、铜矿、稀土或高质量铁矿。
- 某国在一个时期反复经历洪水、干旱、台风或严重冬季。

### 国家观察证据

国家只有在探索、占领、生产或收到有效事件时才能获得证据。证据存入国家本地信号：

- `bio.*`：物种、作物、家畜和野生生物。
- `resource.*`：矿产、渔业、淡水和其他可利用资源。
- `landform.*`：河谷、河口、火山、高原等永久地貌。
- `weather.*`：暂时天气经验，只能在经过 Trigger 累计后转成永久突破。
- `breakthrough.*`：由长期实践、制度或历史事件形成的派生知识。

国家信号必须是本地证据。拥有商品库存不能自动等于发现 `bio.*`；证据必须通过探索、
有来源的事件或受控的域命令进入 Country Runtime。

### 知识突破

Trigger 不拥有国家科技或信号 bitset。它只读取已提交事实，维护去重、计数、窗口和序列，
满足条件后通过 Effect 或明确的 Country 命令请求一个派生信号。例如：

- 在多个格发现同一作物，形成 `breakthrough.crop_selection`。
- 连续经历三次严重干旱，形成 `breakthrough.dryland_adaptation`。
- 经营研究机构并完成若干实验，形成 `breakthrough.experimental_method`。
- 反复使用水力生产方式，形成 `breakthrough.hydraulic_engineering`。

天气和事件窗口不得直接写成永久发现；必须有持久化 Trigger 状态、明确阈值和可重放事件。

### 研究机会与应用

研究条件负责回答“国家现在能不能研究”，而不是直接完成科技。研究完成进入 `pending`，
随后由 Effect 在安全边界产生 Modifier 和其他允许的域命令；全部必要 ACK 成功后，才公开
完成 bit 与 `tech.*` 经济解锁。

## 科技节点的五种类型

每个新增科技至少应明确属于一种类型；重要科技可以组合两种，但不能只有通用百分比。

### 1. 通用基础科技

所有国家都可能发现，但仍要与已有社会能力关联，例如火、文字、基础工具、计数和组织。
它们构成可达的公共骨架，不应要求稀有地图信号。

### 2. 生态适应科技

要求物种、植被或气候证据，打开特定生态生产链。例如：

- 玉米栽培、小麦栽培、块根农业、牧草改良。
- 旱地耕作、梯田、水田、寒地农业。
- 森林管理、草原牧业、沿海渔业。

### 3. 资源利用科技

要求发现资源或形成资源勘探经验，打开采集建筑、加工路线或资源效率，而不是简单把
所有矿物放到同一个工业时代。例如铜、煤、稀土和硫应分别形成不同的工业机会。

### 4. 地理基础设施科技

由地貌与交通条件改变路线：河运、水利、山地道路、港口、远洋航海、火山土壤利用和
高原运输。它们可以改变贸易容量、建设成本、特定建筑条件或运输速度。

### 5. 社会与制度科技

由人口规模、职业结构、研究机构、城市化、社会压力或长期生产实践形成。它们应更多改变
研究组织、职业、建筑经营方式、教育和国家协调，而不是凭空提高所有产出。

## 研究条件设计规则

研究条件按四层组合：

```text
结构前置 AND 证据门槛 AND (可选替代路径) AND (可选实践突破)
```

推荐写法：

```text
tech.maize_cultivation =
ALL_OF(
    TECH_COMPLETED(tech.crop_domestication),
    SIGNAL_PRESENT(bio.maize)
)
```

更深的适应路线可以是：

```text
tech.maize_intensification =
ALL_OF(
    TECH_COMPLETED(tech.maize_cultivation),
    ANY_OF(
        SIGNAL_PRESENT(landform.river_valley),
        SIGNAL_PRESENT(breakthrough.maize_selection)
    ),
    SIGNAL_COUNT(bio.maize) >= 3
)
```

设计时遵守以下规则：

- 关键时代主轴不得依赖唯一稀有信号；稀有信号应进入可选强力路线。
- 对每个硬门槛提供另一种合法获得方式：本地发现、实践突破、事件、远征或未来的贸易。
- `SIGNAL_COUNT` 表示独立证据或观察格数量，不表示拥有多少单位商品。
- 队列被条件阻塞时保留进度，不自动跳过，也不把该领域科技点泄漏到其他领域。
- 研究条件解除后只改变可研究性；`pending` 激活不重新判定条件。
- 未发现的节点不得通过 UI、搜索、连接或辅助文字泄露语义。

## Effect 设计：让完成科技产生真实分化

科技完成不应只挂一个通用领域 Modifier。每个重要科技应引用一个稳定的完成 Effect 定义，
由一个事务原子地完成以下操作中的必要子集：

1. 应用永久、唯一来源的科技 Modifier。
2. 发布“科技采用”或“突破完成”事件，供 Trigger 后续累计。
3. 提交允许的 Country 命令，例如产生 `breakthrough.*` 证据。
4. 提交允许的 Economy 命令，例如开放一个已定义的生产方式或建设意图。
5. 必要时应用短期的试验、动员或适应 Modifier。

Effect 只能计划和提交命令，不能直接写 Country、Economy、Modifier 或守恒账本。流程必须是：

```text
evaluate -> plan -> adapter preflight -> PREFLIGHTED
        -> domain safe commit -> COMMITTED -> ACK
```

复合科技效果的完成 bit 必须等所有必要域 ACK。Modifier 只改变数值，不创建现金、商品、
人口或科技点；物资和建筑解锁仍由 EconomyCatalog 的 `tech.*` 标签执行。

### Effect 的三类配方

#### 永久能力

例如玉米栽培完成后应用：

- 玉米作物家族产出因子。
- 玉米农场的资源利用或适应系数。
- 农业研究效率的小幅加成。

不要只应用全国农业总产出加成，否则玉米路线无法与普通农业区分。

#### 条件化能力

例如水利科技完成后，Effect 可以应用河谷建筑的建设时间和维护效率 Modifier；真正能否
建造仍由建筑的温度、湿度、河流、地形和资源条件判断。

#### 历史回馈

科技采用事件被 Trigger 消费后，可以在累计若干年生产或经历后产生新的突破。这样科技不是
一次性的静态奖励，而是“采用 -> 实践 -> 改良 -> 新路线”的循环。

## 玉米路线完整样例

### 发现与研究

地图生成已经能在符合生态和地理条件的格上产生 `bio.maize`。国家探索这些格后获得永久
本地证据。建议新增：

- `tech.maize_cultivation`：需要作物驯化和 `bio.maize`。
- `tech.maize_selection`：需要玉米栽培，以及至少三处玉米观察证据或长期玉米生产。
- `tech.dryland_maize`：需要玉米选择和干旱适应突破。
- `tech.floodplain_maize`：需要玉米选择、河谷证据和灌溉。

### 经济内容

- `corn_grain` 只由玉米相关科技或早期明确的野生采集路线生产，不再使用无关的手稿科技作为
  门槛。
- 玉米农场使用 `tech.maize_cultivation`，并配置 `cultivate_local_resources` 或现有的
  资源行为与生产气候条件。
- 温度、湿度、耕地、水分和植被决定地块产能；科技决定是否拥有该生产方式以及适应系数。
- 玉米食品、饲料或后续加工品分别挂到相应的加工科技，不能因玉米农场解锁而全部瞬间出现。

### 实践与后续 Effect

玉米农场持续产生真实产出后，经济提交稀疏的累计事实。Trigger 以生产量、持续天数和失败
试种次数形成 `breakthrough.maize_selection` 或 `breakthrough.dryland_adaptation`。
Effect 再应用专属 Modifier 或发布下一项研究机会。

这会形成不同国家的自然分化：河谷国家优先发展水田玉米，干旱国家走旱地适应，高纬国家
可能停留在发现阶段，除非发展温室或寒地农业。

## 路线组合示例

| 环境/发展事实 | 优先路线 | 典型 Effect 结果 |
| --- | --- | --- |
| 河谷、洪水和丰富淡水 | 水利农业、堤坝、河运 | 河谷建筑效率、洪灾适应、国内运输能力 |
| 草原、马匹和低湿度 | 牧业、马匹驯化、陆路物流 | 牧场容量、移动贸易、骑乘相关产业 |
| 海岸河口和航行经验 | 远洋航海、港口、商业组织 | 贸易容量、船舶方法、沿海产业 |
| 高原、山地和水力 | 梯田、水力机械、山地道路 | 高地农业、能源生产、建设路径 |
| 煤炭、铜铁矿和工坊 | 冶金、焦炭、蒸汽工业 | 具体金属产出、机器生产、能源转换 |
| 反复干旱或洪灾 | 旱作、蓄水、灾害治理 | 气候损失降低、特殊耕作、社会稳定 |
| 高人口、学术建筑和识字 | 统计、公共教育、国家实验室 | 研究机构、职业结构、科研成本 |

这些路线不应互相排斥到无法继续游戏。主轴提供基础能力，路线节点提供更强但有条件的专业化；
国家最终可以通过长时间投入补足其他路线，但机会成本、研究成本和地理限制会保留差异。

## 时代奖励的使用方式

`EraRewardCatalog` 已经提供时代里程碑后的确定性三选一、资格过滤、权重规则和 Effect 模板。
它应从通用的“粮食/工业/科研/贸易”主题逐步转为环境和历史证据加权：

- 有河谷和洪灾证据，提高水利国家选项权重。
- 有马匹和草原证据，提高牧业网络选项权重。
- 有海岸与航行证据，提高海洋商业选项权重。
- 有煤、工坊和冶金实践，提高机械工业选项权重。
- 有多个研究信号但生产落后，提高科研追赶选项权重。

权重只改变候选机会，不应静默授予未满足前置的科技。候选计划、选择和事务继续由 PKEF
保存并使用稳定 hash，避免读档后重抽奖励。

- 176 个可研究科技各有唯一 Effect recipe、唯一 Modifier definition 和显式 term IR。
- 39 个生产家族因子及旱、涝、寒、热适应因子在 economy epoch 边界冻结并被生产消费。
- 蒸汽链拆成大气式原型工坊、通用蒸汽机工厂、蒸汽抽水矿井、铁路物流和冶金应用；
  `steam_power` 不再充当跨行业总开关。

### 已完成：派生突破

使用已有 GameplayEventBus、TriggerRuntime 和 Effect Country adapter：

- Economy 在提交边界扫描稀疏 BuildingGroup，并发布已经资格化的实践事实。
- Trigger 维护计数、来源、fire sequence 和幂等；Effect 将结果转成
  `DISCOVER_COUNTRY_SIGNAL`，第一实践格保留为证据来源。
- PKCN v11、PKEF v9、PKTR v4 使用严格当前 schema 与 catalog identity round-trip。

### 已完成：专属数值效果

- 科技 Modifier 已拆到生产家族、研究制度、气候适应、建设和运输消费者。
- Effect 与 Economy 只交换冻结数值/typed POD 命令，热循环不读取字符串或 Dictionary。
- 普通条件和算术继续使用 packed IR；开放式算法仍必须走注册的 C++ behavior。

### 已完成：路线反馈

- 每项科技发布 `technology.adopted`，实践事实可继续形成后续突破。
- EraReward 根据资源/环境信号和已完成 `route.*` 前缀调整候选权重，并保留可见理由。
- 跨国贸易、远征和知识传播仍另行设计，不改变当前国内贸易权威。

## 防止路线失控

- 任何强力路线都至少有一个替代入口或长期补救方式。
- 时代里程碑的候选必须在没有特定稀有资源时仍然可达。
- 地理条件改变效率和机会，不应让玩家无法理解为什么节点被阻塞。
- 永久信号只在永久事实或完成的历史突破上使用；天气窗口保持可重放的 Trigger 状态。
- 不把 Modifier 当作物资、人口、现金或科技点的生成器。
- 不在热循环中进行字符串、Dictionary、Godot Object 或全表扫描。
- 任何新的 Economy/Modifier/Effect 命令都必须有域适配器、幂等键、ACK 和保存契约。
- 未发现科技的名称、效果、前置和连线不能通过 UI 或辅助文本泄露。

## 验收标准

新增一条路线必须至少通过以下检查：

1. 目录编译：稳定 ID、条件引用、拓扑、Modifier key、经济 `tech.*` 标签和 catalog hash。
2. 发现测试：探索、证据去重、不同国家隔离、信号计数和阻塞队列进度保留。
3. Effect 测试：确定性 plan hash、目标 generation、重复命令幂等、跨域 ACK、失败重试。
4. 经济测试：建筑放置、就业、输入、资源扣减、产出、价格和人口/现金/商品守恒。
5. 路线测试：同一地图的不同国家因证据和发展状态得到不同可研究节点和 Effect 结果。
6. 存档测试：PKCN 先于 PKEC，PKEF/PKTR round-trip，catalog mismatch 和截断明确拒绝。
7. 性能测试：Native 热循环无字符串查找和分配；研究/Effect/经济日结不出现全表扫描。

最终目标不是让科技树拥有更多节点，而是让每个节点回答一个清楚的问题：

> 这个国家看到了什么，经历了什么，组织了什么，因此学会了什么；学会以后，它的生产和社会
> 选择又如何改变下一轮发现。
