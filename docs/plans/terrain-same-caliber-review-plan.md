## 0. 一句话

上一轮用便宜的实验推翻了三处错误归因，但又留下两个**测量口径有问题**的负面结论（X1、X2）、

同时有两件事不用再测就能确定是机制缺陷：**脊只通过逐轮抬升进入 SPL，初始水网完全不知道脊在哪**（M1' 只比零假设高 7 pp 的直接原因）；
**像素汇水在河心出口被截断，干流在像素层从不被 SPL 下切**（X2 不可测、X1 偏低的共同根源）。
本计划先修口径，再改这两处机制，最后按「高度分布保真优先」重标 u，并修正三份计划里已被推翻的内容。

## 2. 修口径：X1 / X2

### 2.1 X1 回到原定义，改为相对门禁

**问题**：计划定义「河心像素高度 ≤ 其 3 px 邻域中位数」；实测用的是「7×7 窗口内局部最低」。
后者在以下情况必然失败，而这些都不代表河没在谷里：

- 河宽多于 1 px 时，河心旁边的河道像素与河心几乎等高，任意一个略低即判失败；
- 河流 SDF 带 warp，河心线与 bake 高度最低线有亚像素偏移；
- 河流 SDF 下切（`PK_BAKE_RIVER_INCISE=0.045`）是按 notch 缓降的，谷底在河宽内是平的。

**做法**：

| 指标 | 定义 | 用途 |
|---|---|---|
| X1 | 河心像素（`flow ≥ dem_valley_river_outlet_flow`）高度 ≤ 半径 3 px 圆盘内像素高度中位数的比例 | 主判据 |
| X1s | 7×7 局部最低（上一轮口径） | 只记录，便于对照 |
| X1r | 河心像素高度在半径 6 px 圆盘内的百分位，取中位数 | 连续量，判据边界附近更稳 |

**门禁（相对）**：同一张新 cell 地形、同一 DLL、同种子，
`X1(spl) ≥ X1(carve) − 0.01`。四种子都满足才算通过。
绝对阈值不再设——0.95 的来源是合成锥坡（R5），对真实地图没有依据。

若 `X1(spl) < X1(carve)` 明显（> 0.03），才把「叠加收益不成立」记为结论，并转 §2.3 排查。

### 2.2 X2 作废

河心像素是 wet 出口，汇水累积在出口处 `continue`，面积停在初值 `1/hex_px²`。
「河心像素汇水低于陆地中位数」是实现决定的，不是测出来的。
像素层只负责支流，干流由河流 SDF 给出；「河是否走在汇流主干上」只能在 cell 层回答（§3.4）。

X2 从 `erosion_spl_bake_test.gd` 的 A12 中删除，测试注释写明原因。

### 2.3 若 X1 确实变差的排查（条件触发）

| 实验 | 做法 | 判读 |
|---|---|---|
| E1 | `dem_valley_river_outlet_flow` 0.6 → 0.4 / 0.8 | 出口阈值是否让河心附近的支流汇入点错位 |
| E2 | 关掉河流 SDF 下切，只比 spl 与 carve 的原始谷底 | 区分「侵蚀谷不对」与「河 SDF 不对」 |
| E3 | 统计 X1 失败像素到最近谷底线（局部最低连线）的距离分布 | 亚像素偏移（≤1 px）还是系统性偏离（≥3 px） |

## 3. 同口径新旧对比（cell 层）

### 3.1 公共参照场：E0 版 `ridge_add`

两版的 §1 地台/造山与 §2.55 洋底完全一致，所以 **E0 两版相同**；
新版本来就在 E0 上算 `ridge_add`。以它作为两版共用的「哪里是脊」的定义，比较才成立。

**需要的数据**

| 数据 | 来源 |
|---|---|
| E0 与 `ridge_add(E0)` | 新增 opt-in 诊断 `debug_dump_ridge_e0`（profile 键，默认 false）：base pass 在 §R 之后把两数组放进返回 dict；不改任何计算 |
| 旧最终 E | 冻结数组 `tmp/p5_calib/baseline/seed_*_elev.bin`（已有） |
| 旧陆地/地形 | `*_land.bin`、`*_terr.bin`（已有） |
| 新最终 E、陆地、地形、`hydro_parent`、`has_river` | 当前 DLL 生成 |
| 旧 `hydro_parent` | **未冻结** → 在测试脚本里对旧 E 跑一遍与 post-base 相同的 Priority-Flood 重建（§3.5） |

先验证 E0 一致性：用冻结旧 E 无法直接验证（它是最终 E），所以改为在当前 DLL 上用同种子导出两次 E0 比 hash，
并在代码层确认 §1/§2.55 自 P5 起未被改动（`git diff` 该段为空）。这是本节成立的前提，写进测试开头。

### 3.2 M1'（同口径）

```
脊顶格 = ridge_add_E0 的 6 邻局部极大 且 ≥ 陆地 p75（两版共用同一集合）
分水岭格(版) = 存在邻格，其最终出口（沿该版 hydro_parent 追到海/湖）与本格不同
M1'(版) = |脊顶格 ∩ 分水岭格(版)| / |脊顶格|
零假设(版) = 随机陆地格（同数量，固定 RNG）的分水岭比例
```

报告 `M1'(旧)`、`M1'(新)`、各自零假设、差值。判读：

| 结果 | 结论 |
|---|---|
| 新 − 旧 ≥ 0.05 | 脊抬升确实把分水岭拉向脊，只是幅度小 |
| \|新 − 旧\| < 0.05 | 脊抬升对分水岭位置基本无作用 |
| 新 − 旧 ≤ −0.05 | 退步，需要排查 |

### 3.3 M2b（同口径）

```
高脊格 = ridge_add_E0 ≥ 陆地 p75（两版共用）
M2b(版) = 该版最终 E 上，填洼深度 ≥ hydro_lake_min_depth 且溢流口落在高脊格上的闭合洼地数
```

同时报告「高脊格上的洼地面积占比」，避免只数个数被碎洼地主导。

### 3.4 cell 级叠加：河是否落在脊间谷地

脊抬升计划 §10 真正想要的效果在 cell 层：

| 指标 | 定义 |
|---|---|
| C1 | 河流格高程 ≤ 6 邻高程中位数的比例 |
| C2 | 河流格的 `ridge_add_E0` 中位数（越低说明河越避开脊） |
| C3 | 河流格穿过高脊带（`ridge_add_E0 ≥ p75`）的段数 / 总河段数（峡谷率；不追求为 0，大河横切山带是期望行为） |

旧版河流格同样未冻结 → 用 §3.5 重建的旧 `hydro_parent` + 与 post-base 相同的 `up_count ≥ river_channel_init_cells`
规则得到「旧河流代理」；新版**也用同一代理规则**（而不是 `has_river_arr`）计算，保证两边口径一致。
新版另外报告一次用真实 `has_river_arr` 的值，用来检查代理是否可信（两者 C1 差 ≤ 0.03 才采信代理）。

### 3.5 旧 `hydro_parent` 重建

在测试脚本（GDScript 或 `tools/` 下 Python，与 `tmp/p5_calib/compose.py` 同套环境）里实现：
边界入堆 → Priority-Flood → `parent = 关闭者`（与 post-base 现实现一致，**不用**最陡受体）→ 按出栈逆序累积 `up_count`。
用新版数据自测：对新最终 E 重建的 parent 与 `hydro_parent_arr` 一致率 ≥ 99% 才用于旧版。

## 4. 收益消融：M2 −40% 从哪来

P5 有四个改动，目前只对 M2b 做过消融。对 M2（闭合洼地总数）和 M4（流路直线度）补做：

| 组 | u（脊抬升） | 扩散 κ | 最陡受体 | 膝点压缩 | 说明 |
|---|---:|---:|:---:|:---:|---|
| A0 | 旧基线 | — | — | — | 冻结数组 |
| A1 | 0.03 | 0.08 | ✔ | 取消 | 现状 |
| A2 | **0** | 0.08 | ✔ | 取消 | 去掉脊抬升 |
| A3 | 0.03 | **0** | ✔ | 取消 | 去掉扩散 |
| A4 | 0.03 | 0.08 | ✘ | 取消 | 去掉最陡受体 |
| A5 | 0 | 0 | ✔ | 取消 | 只剩最陡受体 + 线性预算 |

- A4 需要一个**临时** profile 开关 `spl_steepest_receiver`（默认 true，只在本实验用；实验结束删除或保留为诊断键，§7 决定）。
- 膝点压缩已删，无法单独恢复；A5 即为「只留结构性改动」的下界。
- 每组 8 种子（4 × 60×40 + 4 × 200×150），报告 M2、M2b（§3.3 口径）、M4、land_h p50/p90/p99。
- 去掉 u 时 p50 会漂，A2/A5 的 `spl_uplift_rate` 按 §6 的方法补偿到 p50 偏差 < 5%，否则洼地变化会混入高度变化。

**判读**：

| 结果 | 结论与后续 |
|---|---|
| M2 收益主要在 A2 仍保留 | 收益来自扩散/最陡受体，脊抬升主要贡献是视觉 → §6 考虑把 u 再降 |
| M2 收益在 A2 大幅消失 | 脊抬升是 M2 的主因，u 不宜低于当前实测保真点 |
| A3 收益大幅消失 | 扩散是主因，κ 不能降 |

## 6. u 重标（裁决：高度分布保真优先）

**理由**：高度分布直接驱动气候、群系、经济；脊线突出已被 M1' 证明没换来结构收益（§3.2 若推翻此点，回到这里重议）。

**时机**：在 G1（§10）合入之后做。G1 的预叠脊会改变高度分布，先重标再改机制等于白标。

**做法**：

1. 固定 κ = 0.08、最陡受体开、G1 的 `f_pre` 取 §10 选定值；u 与 `f_pre·A_ridge` 一起视为「总脊量」重标。
2. u ∈ {0.010, 0.015, 0.020, 0.025}，每个 u 对 `spl_uplift_rate` 做一维二分，使 8 种子 land_h p50 偏差 < 2%。
3. 在得到的 4 个点上比较 p90/p99 偏差、M2、M2b、M4、M5a。
4. 选择规则：p50/p90/p99 偏差全部 < 5% 的点里，取 **M2 最小**者；并列取 u 较大者（保留更多视觉脊线）。
5. 若 §4 判读为「脊抬升不是 M2 主因」，候选集扩展到 u ∈ {0, 0.005}。

上一轮的可用先验：u = 0.01 时小图 p50 偏差 −0.5%；预计最优点在 0.015–0.020。

**落地**：改 `climate_profile.gd` 的 `spl_ridge_uplift` / `spl_uplift_rate` 与 C++ 兜底默认值（三处同步，沿用上一轮注释约定），
按指纹规则重写基线，提交说明附重标表。

## 10. 修改线：机制修正

### G1 脊参与初始建网（cell 层，`world_ext_generate_base.cpp` §R / §2.4'）

**缺陷**：当前 `ridge_add` 只以 `U_i += u·ridge_add_i` 逐轮进入 SPL。第 1 轮建树时 E 里还没有脊，
水网按 E0 组织；之后每轮抬升量很小，分水岭迁移是慢过程，14 轮内水网基本继承自 E0——
河流大量「先于脊存在」，横穿脊带（M1' 只比零假设高 7 pp；上一轮 S4.2 加轮数 M1' 单调上升也指向这一点）。

**修改**：把脊拆成「初始地形」与「持续抬升」两部分。

```
E_init = E0 + f_pre · A_ridge · ridge_add          （§R 之后、第 1 轮建树之前，仅陆地）
U_i    = rate · relief0_i + (1 − f_pre) · u · ridge_add_i    （每轮）
```

- `f_pre = spl_ridge_prestamp_frac`（新 profile 键，默认 0.5）；`A_ridge` 取 `14 · u`，使 `f_pre=0` 时与现状逐位一致、
  `f_pre` 只改变「脊在第几轮出现」，不改变总量。
- 第 1 轮建树就看到脊 → 水网绕脊组织、分水岭落在脊上；大汇水的河仍可在后续轮次中切穿（先成河峡谷保留）。
- E_init 写入后立刻做一次与 §4 同规则的局部填洼（仅对 E_init 新产生的闭合洼地，`+0.001`），
  防止预叠脊在谷里筑坝——这一步正是旧版「脊在 SPL 后叠加」造坝的反面，必须在建树前消掉。
- 可选（默认关）`spl_ridge_area_feedback`：每轮 `U_ridge_i *= 1 − smoothstep(A_lo, A_hi, A_i)`（原 D1），
  只在 G1 之后 M1' 仍不足时打开。

**验收**（同口径，§3）：

| 指标 | 门禁 |
|---|---|
| M1'(新) − 零假设 | ≥ 0.15（现 0.07） |
| C2 河流格 `ridge_add_E0` 中位数 | 较改前下降 |
| C3 峡谷率 | > 0（大河仍能横切山带），且较改前下降不超过 50% |
| M2 | 不劣于改前 ×1.1 |
| land_h p50/p90/p99 | 由 T9 重标收口，此步只记录 |
| base pass 耗时 | +≤ 2 ms |

`f_pre` 扫 {0, 0.25, 0.5, 0.75}，取 M1' 提升与 M2 的折中点。

### G2 cell 河流汇水注入像素 SPL（bake 层，`bake_erosion_spl.h` / `world_ext_bake.cpp`）

**缺陷**：河心像素（`flow ≥ dem_valley_river_outlet_flow`）是 wet 出口，汇水在此截断，
像素层 `A_hex` p99 只有 1.55 hex²（§1 R4）；**干流在像素层从不被 SPL 下切**，河谷只有固定 0.045 刻刀。
结果是支谷在河边「悬挂」，河道与谷底的关系全靠河流 SDF 的 notch，X1 偏低、X2 不可测都源于此。

**修改**：河心像素不再是出口，改为**带外部汇水的普通像素**。

1. 在 bake 侧用已暂存的 `_gen_river_downstream` / `_gen_river_has` 对 cell 做一次上游累积，得到每个河流格的
   上游格数 `up_cells[c]`（O(n_cells)，< 1 ms）。
2. 河心像素的初始汇水 = `1/hex_px²`（本像素）+ `inject[c] = up_cells[c] · cell_area_hex / n_center_px[c]`，
   其中 `n_center_px[c]` 是该格内河心像素数（把整格上游面积均摊到格内河心像素），`cell_area_hex ≈ √3/2`。
3. 出口只保留真正的水体（海、湖、礁等 `pk_is_water_terrain`）。河心像素进入流向树，按最陡受体向下游传递；
   为避免河心线在格内被受体选择打散，河心像素的受体**优先选同为河心、且所属格等于本格或本格下游格的邻像素**（平局再取最陡）。
4. SPL 对河心像素照常下切；`C` 随注入后的大 `A` 变大，干流获得与汇水相称的下切，支谷自然在汇入处平接。
5. 不变量不变：仍只降、陆地不下海、水体不动；`min_child_h` 约束同样作用于 P3 沉积。

**新 knob**：`dem_spl_inject_cell_area`（bool，默认 true；false = 现状逐位）。

### G3 河道下切随流量（bake 层）

**缺陷**：`PK_BAKE_RIVER_INCISE = 0.045` 对所有河一样深（`world_ext_bake.cpp:1626`），与 `_gen_river_flow` 无关。

**修改**：G2 开启时，河流 SDF 下切改为

```
incise = dem_river_incise_base + dem_river_incise_flow · river_flow(c)      （默认 0.020 + 0.035）
```

并且只在 SPL 未刻够的地方补刻：`e = min(e_spl, e_pre − incise · notch)`，避免与 G2 的 SPL 干流下切叠加成双重深槽。
`river_flow(c)` 用河心像素所属格的 `_gen_river_flow`，河岸像素取最近河心像素的格值（SDF 已给出最近距离，额外存一张格 id 即可）。

**G2+G3 验收**：

| 指标 | 门禁 |
|---|---|
| X1（§2.1 原口径） | ≥ X1(carve) 且较 G2 前 +0.05 以上 |
| X1r 中位数 | ≤ 0.25（河心落在 6 px 圆盘的低四分位） |
| 支谷汇入悬挂 | 汇入河心像素的支流像素与河心高差 p95 ≤ 改前 ×0.5 |
| 干流纵剖面 | 沿 `_gen_river_downstream` 链采样河心高度，逆坡段（下游更高）占比 ≤ 2% |
| 不变量 A1/A2/A10 | 全绿 |
| geometry pass 耗时 | +≤ 10 ms（desktop，release） |

### G4 tile 沟谷对齐汇流（原侵蚀计划 P4，`world_ext_bake_visual_tiles.cpp`）

**缺陷**：tile 近景沟谷由 `pk_relief` 相量噪声按**局部坡向** steer，固定波长平行条纹，与基线汇流网络无关
（侵蚀计划 R7）。

**修改**：

1. 基线 bake 保留一张 `area_hex` 场（R16 对数编码，`log2(A_hex)` 映射到 [0,1]，~1.2 MB @620k），随 bundle 传给 tile pass。
2. tile pass 里双线性采样 `log A`：
   - 沟谷方向：steer 向量混入 `∇log A` 的垂直方向（沟沿汇流方向延伸），权重 `smoothstep(log A_lo, log A_hi, log A)`；
   - 沟谷强度：`gully_amp *= mix(0.6, 1.3, t_area)`，汇流越强沟越深，分水岭附近淡出。
3. 依赖 G2：注入后的 `A_hex` 才含干流信息。

**验收**：tile 近景沟谷方向与基线最陡下降方向夹角中位数较改前下降 ≥ 30%；每层耗时 +≤ 3 ms；
`visual_tile_native_bake_test.gd`、`terrain_detail_continuity_test.gd` 全绿。
