# 目标架构

本文描述迁移方向。除明确列出的落地部分，均为**目标，尚未实现**。当前行为读 [现状](current-state.md)，不能按本文假定已有接口。

## 确定性推进

一次 tick 是有明确输入与提交结果的模拟步，首阶段沿用一天。种子、初始内容版本和有顺序的命令日志应决定结果；帧率、后台线程唤醒、分片预算只决定什么时候完成，不能决定业务结果。同一天重试必须沿用冻结输入和请求身份。

目标顺序为捕获输入、按模块依赖计算、完成跨域请求、发布已提交视图。现有十二域顺序继续作为兼容约束；今天气候在表前先提交、部分域允许软完成，不能把当前提交检查称为全域事务。改变这些规则必须另行迁移并以回放证明。

## 模块描述符

**已落地**：`runtime_module_descriptor.h` 定义 id、域、阶段成员函数、reads/writes 文本、是否限主线程。Host 的十二项表由编译期检查与 `runtime_domain_stage_order()` 逐项核对；执行循环通过表调用成员函数。

**S23已落地声明**：推进频率（cadence）、视图版本、intent类型、store和存档段已登记为只读契约，已迁移读边由文本护栏核对。**目标，尚未实现**：由内核全面检查依赖和所有权、自动排序或禁止所有绕行；当前声明不等于访问隔离。

## 跨模块规则

目标只允许两种交接：读取所有者发布的不可变视图；向所有者提交有明确结果的业务请求（intent）。请求包含稳定身份、目标、日期和去重信息；所有者决定接受、等待或拒绝。消费者不能持有另一模块可写容器，不能绕过所有者补钱、改人口或发布伪成功。

今天仍存在原 runtime 直接引用、共享类私有字段、host 内部重试与点对点处理。依赖棘轮冻结这份现有债务，不能把基线中的边当作永久许可。

## 黄金回放

目标记录每拍每域规范化状态摘要，并链接前一天摘要、输入与命令身份。排除计时、地址和诊断次数；纳入所有会影响后续计算的状态及未完成请求。用重复运行、不同分片、保存恢复和线程方式验证同一条链。

当前固定世界八天回放保留 v1 开局账目、v2 整体经济链，v3 新增七域的已提交逻辑投影。S3-A 修复 Country 命令交接日期后，v4 以独立追加链纳入该域；其余覆盖缺口和验证证据见 [现状](current-state.md)。这仍不是完整十二域状态哈希。运行时 SHADOW/parity 保留原行为，本次没有用黄金用例替代全部对拍；未来在覆盖充分后才考虑删除。

## 存档与显示

目标每模块拥有版本化保存片段，恢复先检查完整性、内容身份和依赖，再安装状态。保存中途状态必须含真实继续所需的数据，不能仅存游标。

当前保存模块与会话模块已有脚本登记机制，但没有与 C++ 每日模块表统一。本阶段不改任何保存字节、ABI 常量、场景或绑定名称。Godot 对象、图像和 GPU 上传继续由主线程负责；VISUAL 域只产生刷新意图。
