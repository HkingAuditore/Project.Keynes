## Item 1 (natural_resource P-cache) 复核后建议暂缓（2026-07-05）
- natural_resource_daily：stride=1、must_run、每 tick 跑，读 cell_temp/cell_moisture
- kernel（natres_step_scalar, world_ext_resource.cpp:70）只 ~8 flops/cell/资源：tn=clamp((T-lo)*inv_span); p=c0+c1·tn+c2·m; v=(reserve+p)·inv_denom; clamp。**已 AVX2 向量化**
- P-cache 只在 (T,M) 跨 tick 不变时命中；climate stride=2 时 T/M 冻结数 tick → 理论可命中
- **但**：缓存 P 只省 3 flops，却新增一条 P 数组的内存读 + 破坏 AVX2 干净块（每 cell/资源加 validity 分支）。此 kernel 是内存带宽/流式主导，非算术主导 → mobile 上大概率 wash 或回归
- 诊断估计省 ~1.2ms 存疑（它把 loop=1.7ms 全归给算术，实际是 T/M/reserve 流式 memory-bound）
- 建议：Item 1 需真机 profile 先确认是算术 bound 还是 memory bound 再决定；不宜盲改（有回归风险）。Item 4/5/6 已是稳收益
