## 天气系统"看起来定死"诊断

- 问题：用户反馈天气没有真实的范围/移动/云图。
- 现状（`scripts/weather_system.gd`）：`_weather_field_enabled = true`（第 87 行）走 `_solve_weather_field`，已经是基于 vapor/cloud/precip/instability/type/intensity 的网格场，考虑温度、水汽 advection、风、地形抬升与背风、洋流异常、植被蒸腾、风辐合、季节相位。**物理建模本身不是定死**。
- 三个让它"看起来定死"的真凶：
  1. **渲染没插值**：`main.gd:182` `day_changed` 一天一 tick；`rendering/weather_layer.gd:143 _process` 不在帧间补间，导致 1 Hz 离散突变（最大元凶）。
  2. **summary fronts 已退化为贴纸**：`_build_field_summary_fronts`（行 737）把 fronts 的 `ttl_days=2 / decay=0 / velocity 未设`，每天从场连通分量重建，没有持续身份与漂移。
  3. **场分辨率 = hex 离散**：`_distribute_weather_field_to_cells`（行 704）逐格写 cloud/precip/vapor，shader 拿到的是六边形常数贴图，无法呈现亚 hex 尺度的连续云图。
- 没建模的：气压/涡度、冷暖锋交汇、三维大气分层、亚 hex 连续 advection。
- 建议优先级：①渲染层 prev/next 双场 + day_phase lerp（性价比最高） → ②summary fronts 恢复 velocity 与跨日身份匹配 → ③上采样到 GPU 双线性 + warp 纹理。

## Phase 1 已完成：风场 2.0（vector_atlas BA → 真实 per-cell advection）

**重大发现修正方案**：调研代码后发现风场已经在 GPU 上了——`WorldData.vector_atlas_tex`（RGBA8）的 BA 通道就是 `wind_field`（世界级 RG8 的 [-1,1] 风分量）；MapBaker 在 bake_world / rebake_*_only 时反复重建。但 `weather_overlay.gdshader` 完全没接它，shader 内 advection 用的是全局常量 `axis = vec2(1.0, 0.22)`。所以 Phase 1 不需要新建纹理，只要把 `vector_atlas` 喂进去并改 advection 路径。

**改动**（4 个文件）：
1. `scripts/rendering/weather_layer.gd`：新增 `_vector_atlas_tex` 字段、`set_vector_atlas_texture()` setter、在 `setup()` 内推入 shader uniform。
2. `scripts/rendering/hex_renderer.gd`：(a) `_apply_uniforms()` 同步把 vector_atlas 喂给 weather_layer（让 rebake 后云风跟上）；(b) WorldData 初始化时调一次 `set_vector_atlas_texture(_world.vector_atlas_tex)`。
3. `shaders/weather_overlay.gdshader`：
   - 新增 `uniform sampler2D vector_atlas` + `uniform bool wind_field_enabled`
   - 新增 `WindSample` struct + `sample_wind(uv)` 函数：解码 BA 通道为 dir/speed
   - `sample_weather_field`（连续场）：advection flow 改用 `wind.dir * mix(4..10) * mix(0.55..1.35, wind.speed)`；warp_strength 也叠加 `wind.speed * 4`，让强风区域云团撕扯更剧烈；axis 输出也跟随真实风向，使下游 rain_field 方向与流动一致
   - `sample_front_field`（fronts 团块）：`flow_dir = normalize(ax + wind.dir * 0.35)`，front 整体身份保留但内部按真实风扰动；`flow_speed *= mix(0.9, 1.25, wind.speed)`；`best.axis = flow_dir`

**fallback**：`wind_field_enabled=false` 或局部风速 < 0.05 时，shader 退回旧的 axis-only 路径，视觉不退化。

**预期效果**：东风带与西风带云朝相反方向流；季风走廊云带能看到弯转；强风区云团撕扯感明显；fronts 内部不再整体平移而是有局部旋臂。

## Phase 2 已完成：高/中/低三层云 + 蓝噪声 jitter

**核心改动**：在 `weather_overlay.gdshader` 内一次性加完三件事，不增加任何外部资产或 GD 端配套（Phase 0 的 field×fronts 融合已在那时做完，所以本 Phase 只剩"多层云 + 蓝噪声"）。

**改动明细**（仅 1 个文件：`shaders/weather_overlay.gdshader`）：

1. **新增 hash-based 蓝噪声替代品**（行 ~92-103）：
   - `hash21(vec2)` + `blue_jitter(wp, scale)`：用 golden ratio 1.618 解相关，输出 [-1/scale, 1/scale] 的伪蓝噪声偏移。
   - 替代外部蓝噪声纹理：项目里 `assets/weather/` 目录尚不存在，引入新资产会触发导入流程，hash-based jitter 在视觉上足以破除 value_noise 低频段的双线性网格感。

2. **新增 `sample_high_cloud(wp, axis, intensity)`**（行 ~109-125）：
   - 高云/卷云带，沿 axis 方向**各向异性拉伸**（频率 0.0035 沿风、0.011 垂直），生成纤维状条带。
   - 二次纤维化：再叠一层 fbm × 3.7 频率得到"羽毛"质感。
   - 推进慢（world_time × 0.55），仅在 storm/monsoon 系统上空可见。

3. **新增 `sample_low_fog(wp, axis, intensity, biome_weight)`**（行 ~131-147）：
   - 山雾/低云，强 domain warp（offset 系数 11.0）让边缘极破碎。
   - 雾不沿风向拉伸（贴地各向同性），但缓慢漂移（× 1.4）。
   - `biome_weight=0`（平原/海洋）时直接 return 0，避免雾覆盖整张地图。
   - 加 sin 呼吸项（频率 0.32）模拟雾的浓淡变化。

4. **`wind_domain_warp` 加 blue_jitter**（行 ~180-188）：
   - 在原有 advection + fbm warp 基础上叠加 `blue_jitter(wp, 0.05) * 0.5`。
   - 系数 0.5 保证只是细微抖动，不改变云团整体形状，仅破网格感。

5. **新增常量 `B_HILL=5` / `B_MOUNTAIN=6`**（行 62-63）：与 `world_map.gdshader` 一致。

6. **`fragment()` 重组**（行 ~461-563）：
   - 提前采样 `biome` 与 `mountain_w`（B_MOUNTAIN=1.0、B_HILL=0.55、其他=0），让多层云能复用。
   - 计算 `cirrus`（仅 storm/monsoon 且 cloud > 0.05）和 `low_fog`（仅 mountain_w > 0 且非水面）。
   - `has_layer` 扩展：cloud / precip / cirrus / low_fog 任一非零都进入主渲染。
   - **山雾**叠在云阴影之后、降雨之前：颜色 `mix(冷灰, 暗冷灰, tod_night_factor)`，强度 0.62。
   - **高云**叠在最上层（在 fog_breathe 之后、闪电之前）：颜色 `mix(白, tod_sun_color, 0.35)` 再 `mix(夜冷蓝, tod_night_factor)`，受日落金光自然染色。

**视觉跃迁预期**：
- 一眼能看出三个尺度的空间分层：山脚薄雾 → 中层主云团 → 高空卷云带

## Phase 3 已完成：雨幕 mask + 锋面散度 + 积雪累积

**Phase 3a — 雨幕 mask 化 + per-cell 风向 + rain shaft**（仅改 `shaders/weather_overlay.gdshader`）
- 重写 `rain_field()`：precip<0.20 早 return；雨向 `dir = normalize(wind_dir*0.55 + (0,1)*0.45)`，把重力分量与风方向加权混合，避免雨"水平飘"违和。

## Phase 3 四次调参：发现 advection 函数的根本 bug

## Phase 3 第七轮（v7）— 局部 bug：山地迎风坡"五年连续 RAIN"

**症状**：v6 全图分布正常，但某一格连续多年 RAIN 不消。

**根因**：地形抬升 precip 自我维持环路（与 v6 全境横贯无关）。
- `_orographic_lift_for_cell` 是纯几何函数（cell.elevation - upstream.elevation）
- 山不动 + 西风带方向稳定 → 同一格每天获得相同 lift（0.5~0.8）
- lift 同时给 cloud（×0.35）、precip_raw（×0.18）、instability（×0.35）三路加成
- 即使 vapor 已被消耗光，lift 仍能凭空生成 cloud/precip → max-decay 持留 → 永久 RAIN

**v7 修法**（`scripts/weather_system.gd` L539-579）：
- 引入 `lift_supply = max(lift, 0) × clamp(vapor - 0.20, 0, 1)`：vapor 不足时 lift 失效
- cloud / precip_raw / instability 三路 lift 贡献全部改用 lift_supply
- max-decay 的 floor 也乘 `vapor_floor_factor`：vapor < 0.20 时旧 precip 强制放空
- L542 背风沉降减湿（lift<0 时 vapor += lift × 0.22）保留不动——这条没问题

**物理直觉**：山地迎风降水必须由"上游飘来的水汽"供给，不能凭空产生。这就引入了真正的"局部水汽预算"——上游 advect 来 vapor → 山坡消耗成 cloud/precip → vapor 跌下来 → 下一天 precip 也跌 → 持留环路被打破。

**预期**：山地迎风坡仍是降水带（视觉正确），但持续时长由风从海上送水汽的速率决定，不再"五年连下"。


## 性能优化（v8）— 单帧 451ms → ~100ms 目标

**症状**：fast tick #1715 总耗时 451ms，weather_refresh 占 439ms。
- weather_tick=80ms（adv=70ms 是 v5 advect_steps 翻倍代价）

**field_bake 350ms 根因**（`rendering/map_baker.gd:1949 bake_weather_field_only`）：
- `derived_size` = 1024 × ~600 = 600k 像素（HM_MAX_DIM=1024）
- 每像素 4 次 `Dictionary.get()` + 3 次 `int(round(× 255))` + 4 次 `clampi`

2. **Downsample 4×**：weather_field_tex 是 hex-constant 数据，shader 端 nearest 采样，全分辨率纯浪费。1024×600 → 256×150（像素数 1/16），最终耗时预计 ~20-30ms（比纯 cache 的 ~100ms 还狠）
3. 双管齐下，预计 field_bake 350ms → 15-25ms（−93%）

**未优化但已记录的下一步**（v9 候选）：
- advection 70ms：`_neighbor_aligned` 每次 6 邻居 cube_to_world × 6 跳 × 2400 cells = 86k 次

- 预计 70ms → 10-15ms

**约束**：物理逻辑 v7 完全不动，只动渲染层和缓存。视觉零差异（hex 边界本就由 enum_atlas_tex 决定，weather field 只贡献"内部颜色"）。

## v9 weather_field_bake：逐 hex 替代逐像素

3. vapor_floor_factor 同步改为 `(vapor-0.10)/0.40`，避免强风带误掐

**保留 v7 物理底线**：vapor=0 时 lift 仍为 0（不会"凭空生雨"），五年连续雨的环路依然断绝。

## v9c 内陆湖面修复

**症状**：地图中央大湖完全没有云雨，周围陆地却有正常天气。

**根因诊断**：
1. **ocean_an=0**：LAKE 没有 ocean_current，`_avg_ocean_anomaly_at` 返回 0 → `ocean_mul` 锁在 1.0；而海面平均 0.8-1.4。湖面 evap 比海面少 20-40%。
2. **advect 摊薄**：v5 把 advect_w 调到 0.65-0.95（风权重主导），LAKE 上风邻居是陆地（vapor 低），高 advect_w 直接把湖面 vapor 拉到陆地值。
3. **cloud 公式里 `ocean_an * 0.12` 加成**：湖面拿不到（=0），损失这一路云生成源。

**v9c 改动**（`weather_system.gd:531-580`）：
1. **湖面 advect 降权**：`if is_lake: advect_w = clampf(advect_w * 0.5, 0.20, 0.50)`，让 base_moisture 主导
2. **虚拟洋流异常**：`effective_ocean_an = 0.20 if is_lake else ocean_an`，让 evap × ocean_mul 略高于平均
3. cloud / instability 公式里把 `ocean_an` 替换为 `effective_ocean_an`，让湖面也享受洋流加成路

**判定条件**：`int(cell.terrain) == TerrainType.TERRAIN.LAKE`。海洋系（OCEAN/COAST/REEF/KELP/SEA_ICE）走原 ocean_an 路径不变。

## v9d 河流同理修复（轻度版）

**思路差异**：河流不是独立 terrain（cell.has_river 属性），河带只占 cell 一小部分，周围还是陆地——给湖泊那套强度会让"河流穿过的整片陆地"湿润化。所以参数全部温和化。

**v9d 改动**（`weather_system.gd:531-580, 745-760`）：
1. **advect 轻度降权**：`elif has_river: advect_w = clampf(advect_w * 0.85, 0.55, 0.85)`（湖是 *0.5 → 0.20-0.50；河是 *0.85 → 0.55-0.85）
2. **虚拟异常下限**：`effective_ocean_an = maxf(ocean_an, 0.08)`（湖是固定 0.20，河只设下限 0.08）
3. **自身河流 evap +0.012**：补上"邻居有水 +0.018"的对称项（自身有河之前没加成是逻辑漏洞）

**判定**：`has_river = (not is_lake) and cell.has_river and not on_water`，三层互斥（海洋/湖/河），不会重复加成。

**预期**：河谷地带（especially 沙漠或干燥区域里的河）会出现明显的"沿河湿润带" → 局部云量增加，但不会泛滥到整张地图都湿。
