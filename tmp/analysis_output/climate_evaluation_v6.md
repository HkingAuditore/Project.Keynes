# Project Keynes 气候模拟评估 v6 — 降水 / 天气 / 温度连续性 专题

> 数据: `tile_data_record_20260612_130635.csv` (1313 MB)
> 规模: 1,315,200 行, 2400 cells × 548 ticks (tick 518 → 1065，约 0.5 模拟年)
> 水体比例: 53.3% (1278 / 2400)
> 关注问题：① 降水是否过多 ② 天气生消是否符合自然规律 ③ 温度是否在局部 tick 内 ping-pong / 跳变

## 三、天气生消评估

### 3.1 全局类型分布（type 0..5）

| type | count | ratio | 物理含义（推测） |
|:----:|:------|:------|:---------------|
| 0 | 835,888 | **63.6%** | 晴 / 默认 |
| 1 | 288,890 | 22.0% | 多云 |
| 2 |  48,369 |  3.7% | 阴/雾 |
| 3 |  84,049 |  6.4% | 雨 |
| 5 |  58,004 |  4.4% | 雪 |
| 4 | (缺失) | 0% | — |

整体比例可解释，但 **type 4 全程零样本**。

### 3.2 转换/过渡指标的反常

| 指标 | 值 | 解读 |
|:-----|:----|:-----|
| transition_count_total | 1,085,134 | 平均 0.825 次/cell-tick — **过高** |
| transitioning_count_total | 1,310,616 | **99.65%** cell 处于 alpha>0 的过渡中 |

**矛盾点**：99.65% 的 cell 长期处于"transition"状态，但同时 type 分布又稳定。

### 3.3 案例诊断 — `weather_prev_type_arr` 字段未刷新

cell 69（南极陆地）连续 21 个 tick 的状态：

```
tick   type  prev  target  alpha
 518     0     3     0     1.00
 519     0     3     0     1.00
 520     0     3     0     1.00
 ...    ...   ...    ...   ...
 538     0     3     0     1.00
```

* `type=target=0`：当前 = 目标 = "晴"，理应为静止态。
* `prev_type=3`：永远停留在过去的"雨"状态，**该字段未被同步推进**。
* `transition_alpha=1.0`：永远在"过渡完成边缘"，但既然 type=target，理应切回 alpha=0 静止态。
* 结果：`(type != prev_type)` 总是为真 → 我的 transition 统计被假阳性误导，"82.5%/tick 切换"实际并不存在。

### 3.4 真转换 — 停留段长度（按纬度带）

按"上一 tick `type_arr` 不同视为真切换"统计停留段：

| 纬度带 | 段数 | mean | median | p25 | p75 | p99 | max |
|:-------|:-----|:-----|:-------|:----|:----|:----|:----|
| 0.0-0.1 | 1091 | 49.5 | 22 | 11 | 52 | 343 | 534 |
| 0.1-0.2 | 2613 | 46.5 | 22 | 11 | 52 | 283 | 353 |
| 0.2-0.3 | 2490 | 47.6 | 22 | 11 | 52 | 320 | 478 |
| 0.3-0.4 | 2133 | 45.7 | 23 | 11 | 55 | 255 | 534 |
| 0.4-0.5 | 1631 | 51.9 | 25 | 12 | 57 | 337 | 526 |
| 0.5-0.6 | 1369 | 55.9 | 25 | 12 | 62 | 356 | 526 |
| 0.6-0.7 | 2236 | 48.8 | 25 | 12 | 59 | 278 | 494 |
| 0.7-0.8 | 2561 | 43.1 | 22 | 11 | 44 | 300 | 428 |
| 0.8-0.9 | 2707 | 39.8 | 22 | 11 | 43 | 321 | 415 |
| 0.9-1.0 |  976 | 52.7 | 25 | 11 | 57 | 369 | 469 |

**评估**：
* 停留段 median ≈ 22 tick，长尾到 300+。这本身**合理** — 大尺度天气持续 1-数日。
* 但 cells 数（即真切换次数）相对稀少：以 lat 0.5-0.6 为例，本带 1369 段 / (n=131520) = 1 次切换/96 tick，与上面 99.65% 的"过渡中"严重矛盾。

### 3.5 综合诊断

* 真实天气转换率合理 (`~22 tick 中位数停留`)。
* 然而过渡子系统 (`transition_alpha`) **失去了与 `weather_prev_type` 的同步**，长期粘在 alpha=1.0 不归零。
* `prev_type` 似乎被某个早期阶段写入后**未再被更新**，导致后续看起来一直在"假转换"。
* 推测根因：一旦目标 type 与 source type 都到达 alpha=1，应该执行 `prev_type = type, alpha = 0` 的"过渡完成提交"，但这一步被跳过。

**关键模式**：

### 4.3 全局 11-tick 节拍（决定性证据）

`mean|ΔT| > mean+2σ` 的脉冲 tick 列表：
```
[794, 805, 816, 827, 838, 849]  ← 间隔严格 11
```
**间隔统计：mean=11, min=11, max=11, mode=11, sample=[11,11,11,11,11]**

→ 全场温度每隔 11 个 tick 同步出现一次显著扰动，与 `weather_prev_type` 的整体过渡机制周期完全吻合。

### 4.4 案例 1 — 标准 ping-pong（cell 69, lat=0.026 南极陆地）

| tick | T | T_prev | precip | insolation | type/prev/target/α |
|:----:|:---|:------|:------|:----------|:--------|
| 518 | 0.156 | 0.096 | 0.016 | 0.969 | 0/3/0/1.0 |
| 519 | **0.214** | 0.156 | 0.016 | 1.000 | 0/3/0/1.0 |
| 520 | **0.149** | 0.156 | 0.016 | 1.000 | 0/3/0/1.0 |
| 521 | 0.149 | 0.156 | 0.016 | 1.000 | 0/3/0/1.0 |
| 525 | 0.149 | 0.156 | 0.031 | 1.000 | 0/3/0/1.0 |

ΔT 序列：+0.058 → -0.065 → 0 → 0 → ... → +0.077（**完整的"上跳-回落-平台"模式**，间隔约 11 tick）。
`temp_arr_prev` 字段几个 tick 内不更新（一直 0.156），说明它是"slice 基准" 而非"上一 tick"。

### 4.5 案例 2 — 极端跳变（cell 1539, lat=0.64 北中纬陆地，max&#124;ΔT&#124;=0.319）

| tick | T | precip | insolation |
|:----:|:---|:------|:----------|
| 980 | 0.271 | 0.052 | 0.732 |
| **981** | **0.591** | 0.052 | 0.785 | ← +0.319！|
| 982 | 0.566 | 0.052 | 0.785 |
| 988 | 0.544 | 0.049 | 0.785 |
| 989 | 0.417 | 0.049 | 0.785 | ← -0.127 |
| 990 | 0.321 | 0.049 | 0.785 | ← -0.096 |

**+0.319 的瞬变**对应温度全幅 32%。insolation 同时只小幅上升（0.732→0.785），物理上不足以解释这种突跳——这是**计算输出未做时间滤波 / 弛豫**，让某次 thermal 求解结果直接覆盖了上一帧。

## 五、问题汇总与优先级

| # | 问题 | 严重度 | 量化证据 | 推测根因 |
|:--|:-----|:-------|:---------|:---------|
| 1 | **降水全境化**（99.93% cell-tick 在下雨） | **P0** | 极地陆地都全程降水 | 降水生成阈值过低 / 没有"无雨"判定通道 |
| 2 | **温度 11-tick 全局脉冲** | **P0** | spike 间隔精确为 11 | 某个 daily 阶段（thermal/insolation/SLP-wind）每 11 tick 触发一次重写覆盖 |
| 3 | **温度 max&#124;ΔT&#124; 单 tick=0.319** | **P0** | cell 1539 980→981 | thermal_finalizer 输出未做相对上一帧的限幅/弛豫 |
| 4 | **陆地 ping-pong 强反转 4-9%** | **P0** | 陆地中纬最严重 | 11-tick 节拍 + 陆地热惯量低 → 上跳后被弛豫拉回 |
| 5 | **天气过渡卡死**（99.65% alpha>0） | **P1** | type=target 时 alpha 仍=1，prev_type 不刷新 | 过渡完成时缺失 commit：`prev_type=type; alpha=0` |
| 6 | 降水节拍不连续（同值持续多 tick） | P2 | mode=12，min=2，max=93 | 降水属于 slice 输出，不是每 tick 求解 |
| 7 | 降水陆海结构异常（陆地热带 75%+ 重雨） | P2 | lat 0.4-0.6 陆 heavy 75-78% | 缺乏副热带高压抑制 / 蒸发-凝结模型偏强 |

## 六、修复建议（按优先级）

### P0-1：断言并修复温度的 11-tick 脉冲源

* 验证哪个阶段每 11 tick 触发一次：很可能是 `phys_daily_wind_tick_idx` 模块或 `phys_psi_init` 的某个阶段。
* 在 thermal commit 处增加："当 |T_new - T_old| > 阈值（如 0.05）时，应用最大斜率限制（比如 0.02/tick）"。

### P0-2：降水阈值修正

* 增加判据：当 cloud_water < threshold 或 vapor < threshold 时 precip = 0。
* 目标：将 wet_ratio 降至 30-50%。

### P0-3：温度变化弛豫

* 任何 thermal 子模块输出 T_new 时，先做 `T = T_old + clamp(T_new - T_old, -dT_max, +dT_max)`，dT_max 建议 0.03 (per tick)。
* 这样可同时压制 max|ΔT| 与 ping-pong 强反转。

### P1：天气过渡完成提交

* 在每个 cell 的天气更新末尾添加：`if alpha >= 1.0 and type == target_type: prev_type = type; alpha = 0`。
* 应能将 transitioning_ratio 从 99.65% 降至与真转换率匹配（约 1-5%）。

### P2：天气类型 4 缺失

* 检查类型 4（雷暴？冰雹？）的触发逻辑是否完全没有路径。
