## 0. 结论

1. **大方向可以实施，但离「新卡 = 只改生成器」（§19 验收判据）还很远。**
   - 已上线的 program 卡约 26 张：12 张 SELF、9 张溢出、5 张条件。
   - 179 张设计卡里，多数至少还缺一项 C++ 能力。
2. **已经就绪的有三块**：选择器骨架、tag 表、metric 通道（0..67）。卡池机制 X6/X15 也基本齐全。
3. **缺口分三类：**
   - **(a) 空间派生量**：X2 邻接、X8 上下游、X12 水系/边境、X1 的多源叠加与半径 > 2。
   - **(b) 时间态**：X4 事件叠层、X13 气候累计、tag 迟滞。
   - **(c) 跨域只读量**：X9 家族、X10 时代/科技、X11 税、X14 民心。
   - 三类各有标准解法，见 §3。不要逐卡写特例。
4. **X5 的范围/阈值/上限类覆盖不能放在 Effect 的共享模板里。** 只能在 Ideology 解析阶段按国家覆盖。

## 3. 三类缺口的标准解法

### 3.1 总原则：谁拥有数据，谁就计算派生量

| 层 | 负责 | 不负责 |
|---|---|---|
| **Economy**（worker 上的 COMMIT） | 每格原始量 → tag 位图、每格派生列（邻接计数、连通块、源计数、迟滞、累计器）；发布不可变快照 + 修订号 | 不知道卡牌 |
| **Ideology**（解析层） | 把「卡 × 等级 × 协同」编译成「哪个列/哪个 tag 位图 → 哪个 stat、系数多少」，并做按国家的 X5 覆盖 | 不扫格子 |
| **Effect / Modifier** | 国家级和少量实例级效果的生命周期、事务、存档 | 不承担「每格一个实例」的大批量路径 |

每格卡最终走「系数平面」：Economy 读每格 stat 时计算 `base + Σ_program coef[country][program] × f(列值或位)`。完整设计见 Doc 03 §4。本文各扩展都写成「新增哪些列 + 系数怎么算」。

### 3.2 a 类：空间派生列

- **输入**：tag 位图、`_building_neighbors`、领土 CSR、河流/运河掩码。
- **输出**：每格 `uint8/uint16` 列，SoA 布局，按需注册。只有目录里真正用到的列才计算。
- **列的声明**：生成器在 catalog 里输出 `derived_columns: [{kind, tag_id, radius, ...}]`。Economy 配置时编译成一张列表，按 kind 分发到对应的核函数。
- **增量更新**：COMMIT 时先算 tag 位图的差分 `changed = new ^ old`，只对变化的格及其 R 环邻域修正计数。连通块用「变化少就局部 BFS，变化多就全量 union-find」。
- **存档**：不存，整体可由当期状态重算。迟滞平面除外，它属于 b 类。

### 3.3 b 类：时间态

- 属于「历史」，必须存档，否则读档前后的结果会不一致。
- 归属：
  - 格级历史（干旱天数、tag 迟滞的上期位）→ Economy 存档。
  - 卡级历史（X4 层环）→ PKID 存档。
- 事件源统一使用 COMMIT 差分事件流（见 §4.4）。不允许在理念侧轮询。

### 3.4 c 类：跨域只读量

- 不要再往 `FAMILY_METRIC_COUNT` 里堆新 id。每加一个 metric，每个实例的 metric slab 就多一列，参见 Doc 03 §2.1。
- 分两种形态：
  - **国家标量**（时代、科技位、民心、国库比、理念侧计数）：在 Ideology 内部维护一个 `CountryScalarTable`，每天或在结构变化时从源头拷贝，只用于计算系数。系数 = f(标量)，国家级效果直接用 Effect 的国家实例。
  - **每格量**（家族影响、每格税率）：作为 a 类的派生列，由 Economy 在 COMMIT 时从对应域的快照里聚合。

### 3.5 生成器 DSL 的统一扩展

```python
# 系数来源（coef source）
per_cell(stat="economy.city.output_factor",
         where=Tag("river"),                          # 位图过滤
         scale=Column("neighbor_count", tag="mine", radius=1),  # 派生列
         per_unit=0.02, cap=Cap(units=5),             # 多源上限
         country_scale=CountryScalar("era_gap"))      # c 类标量
```

- 生成器负责三件事：类型检查；列去重（多张卡引用同一列只算一次）；输出 `derived_columns` 和 `cell_programs`。
- 新增的 kind 必须在 C++ 端有白名单。未知 kind 在配置时拒绝，fail-closed。

## 4. 逐项方案

每项按同一个格式给出：**归属域 / 数据源 / 存储与派生 / 存档 / DSL / 测试**。

### 4.1 X1 逐地块（X1-b：多源叠加 + 任意半径）

- **现状**：`TAG_SOURCE_R1/R2` 做的是并集。两个矿场相邻的格只吃到一份，而且在实例层面也做不到叠加（P2-A）。
- **归属域**：Economy（派生列）+ Ideology（系数）。
- **数据源**：源 tag 位图、`_building_neighbors`。
- **派生**：列 `source_count[tag, R]` = 半径 R 内命中源 tag 的格数。
  - R ≤ 2：直接累加邻居表。
  - R > 2：对每个源格做有界 BFS。如果源很密，改用六边形距离的分离式前缀和。
  - 增量更新：源位翻转时，对其 R 邻域 ±1。
- **系数**：`effect = min(source_count, cap) × per_source × country_scale`。
- **存档**：无。
- **半径上限**：建议 R ≤ 4。在六边形网格上，R = 4 是 61 格，增量更新的成本可控。生成器校验这个上限。
- **测试**：构造两个源格夹一个格的局面，断言中间格吃到 2 倍；移除一个源 → 变为 1 倍；R = 3 的用例覆盖 BFS 路径。

### 4.2 X2 邻接

- **归属域**：Economy。
- **列**：
  - `neighbor_count[tag]`：6 邻中带 tag 的格数，0..6。
  - `component_size[tag]`：同 tag 连通块的大小，用 uint16，饱和到 65535。
  - 可选 `component_id[tag]`，给 UI 高亮用。
- **算法**：邻接计数增量更新。连通块用 union-find，位翻转数超过阈值（如 1% 格）时全量重建，否则对涉及的块做局部 BFS。
- **已有的 metric 54（邻格人口）**：保留，但以后按列的方式实现。
- **DSL**：`Column("neighbor_count", tag=...)`、`Column("component_size", tag=...)`，可以配合 `where=Tag(...)` 使用。
- **测试**：在小地图上手工摆出 tag，断言两列的精确值；翻转一个桥接格，断言块的拆分与合并。

### 4.3 X3 职业

- **现状**：metric 51..53 只有主导职业。
- **方案**：目录声明需要的职业类集合，比如 `artisan / merchant / miner`。Economy 在 COMMIT 时按格算 `profession_class_share[class]`（Q16 存在 uint16），作为派生列。
- 只计算目录引用到的类。映射表「职业 → 类」由生成器输出。
- **测试**：给格子注入已知的职业人口，断言份额。

### 4.4 X4 事件叠层（工作量最大）

- **归属域**：事件由 Economy 产生，层环由 Ideology 维护。
- **事件源**：Economy 在 COMMIT 时产出「差分事件流」`CommitEvent{kind, country, cell, value}`。初始事件类型：
  - 新职业出现
  - 人口跨过阈值（复用 tag 位翻转）
  - tag 进入 / 退出
  - 灾害（X13）
  - 并入注入的非 Economy 事件：重抽、时代变更（由 Ideology 或 Country 直接注入同一条队列）
- **层环**：
  - 每个 `(country, program, scope)` 一个定长环，scope 可以是国家，也可以是格。
  - 环容量 = program 的 `max_stacks`，生成器限制 ≤ 16。
  - 环元素存 `expires_day`。
  - 存储按 program 打包成稀疏表 `unordered_map<key, Ring>`。更好的做法是按 program 分桶的开放寻址表。
- **每日处理**：
  - 层的过期用按 `expires_day` 排序的全局小顶堆或分日桶处理。没有层到期时成本为 0。
  - 层数变化后，写回系数平面的「层数列」。如果一个 program 只有国家 scope，就改写 Effect 国家实例的 `desired_stack_count`。
- **存档**：PKID 7→8，写入层环表，按 key 排序以保证确定性。事件流本身不存，因为是当天消费的。
- **worker**：层环属于理念权威状态，要进 IDP2 POD，ABI 5→6。否则 worker 和主线程会分叉。
- **DSL**：

```python
on_event("new_profession", scope="cell", add_stack=1, max_stacks=5, duration_days=360,
         per_stack=PerCell(stat="economy.city.output_factor", value=0.01))
```

  - 只有这种绑定了 `on_event` 的 program 才允许使用 `ADD_STACK + DURATION`（与 P1-E 的生成器拦截对应）。
- **测试**：
  - 注入 3 次事件，间隔 10 天 → 层数依次为 1/2/3，每层在各自的到期日消失。
  - 超过上限时替换最早的层。
  - 存档/读档前后逐位一致。
  - worker 与同步路径结果一致。

### 4.5 X5 协同改卡

- **倍率**：已有，先修 P1-D。
- **范围 / 阈值 / 上限 / 附加条件：不要在 Effect 模板上做。** 原因是模板被所有国家共享。
- **方案**：在 Ideology 维护按国家的覆盖表 `ProgramOverride{radius, tag_threshold_delta, cap, extra_condition_tag}`，由激活的协同在编译期生成。
  - **范围 / 上限**：解析时把 program 映射到另一个派生列变体，比如 `source_count[tag, R+1]`。生成器会把所有可能用到的变体都声明成列，所以运行时不需要动态建列。
  - **阈值**：同样通过预声明的 tag 变体实现，比如 `populous@P1` 和 `populous@P1-20%`，在解析时切换。这样 tag 表保持不变。
  - **附加条件**：系数平面里的 program 过滤位图从 `A` 变成 `A & B`，仍然在解析时确定。
- **存档**：无，覆盖表可以由协同位重建。
- **触发重算**：复用 P1-D 的反向索引，翻转后把受影响的卡标脏。
- **测试**：协同激活前后半径从 1 变到 2，命中格和数值都符合预期。

### 4.6 X6 卡池操作

- **复制相邻槽**：需要「槽位顺序」这个概念。现在 `active_indices` 按 ideology_id 排序，没有槽位。
  - 方案：`IdeaState` 增加 `slot_index`（PKID + IDP2），装备时分配最小的空槽。
  - 「复制」在解析时读相邻槽卡的 program，生成一份按倍率缩放的系数。
  - 不要复制 Effect 实例。
- **免费抽取**：新增命令 `FREE_DRAW`，抽卡时不扣点。接入现有 offer 流程；受保底分区约束，要写清楚「免费抽取是否推进保底计数」。
- **测试**：槽位在卸下/装备后的分配是确定的；复制效果随相邻卡变化而刷新。

### 4.7 X7 计数（理念侧那一半）

- 已装备卡数、某路线卡数、激活协同数是 Ideology 自己的状态，**不应该做成 Economy metric**。
- **方案**：在 `CountryScalarTable` 里加 `equipped_count`、`route_count[route]`、`synergy_count`。在 `rebuild_country_derived` 和过渡 ACK 时更新。系数 = f(标量)，变化时把依赖它的卡标脏。依赖关系用反向索引「标量 → program」。
- **测试**：装备第 N 张同路线卡，依赖该计数的卡数值正确变化；不相关的卡不被重算。

### 4.8 X8 上下游

- **列**：
  - `supplier_within[good_chain, R]`：R 格内是否有上游供应者，bit 或计数。
  - `neighbor_distinct_goods`：邻格不同产出品的种数。
- **数据源**：每格产出品集合（metric 45/46 的来源）、生产链表。
- **实现**：把「产出品 g」当成位图，复用 X1-b 的 `source_count` 核函数。「上游」就是对该链所有上游品的位图取并集。种数用邻格物资掩码的 OR 再 popcount，前提是物资种类 ≤ 64；超过就用多字。
- **测试**：摆出一条 矿→冶炼→工坊 的链，断言工坊格带上游位，移走矿以后消失。

### 4.9 X9 家族

- **数据源**：Family runtime 的家族→格影响（家族 buff 已经有按格的概念，见 `economy_runtime_family_buff.cpp`）。
- **列**：`family_influence`（格内所有家族影响力之和，Q16）、`family_count`。在 COMMIT 时聚合，家族状态取上一期冻结快照。
- **注意**：家族是另一个权威域，要先确认它在 COMMIT 时有可读的冻结视图（参考 `project-keynes-family-runtime` skill）。没有的话先补视图，不要跨线程直接读。
- **优先级**：低（M5）。

### 4.10 X10 时代 / 科技

- **数据源**：Country 冻结的科技位和时代里程碑（`country_runtime.h` 约 1023 行）。`requirements_met` 已经在用 `has_technology`。
- **方案**：
  - c 类国家标量：`current_era`、`era_gap(card) = current_era - card.era`、`has_tech[t]`。
  - 卡的时代由生成器写入定义。
  - 时代变更时发一个 X4 事件，并把依赖 `era_gap` 的卡标脏。
  - 科技位变化用 Country 的研究完成信号触发，不要每天轮询。
- **测试**：进入新时代 → 依赖 `era_gap` 的卡数值变化；完成一项科技 → 条件卡激活。

### 4.11 X11 税

- **现状**：metric 55 只有均值。

### 4.12 X12 水系 / 边境

### 6.1 审计校正（2026-10-21，脚本生成）

`tools/ideology/audit_card_reachability.py` 已写好并跑过，矩阵入档在设计文档末尾。
179 张卡：**可直接做 9、缺 1 项 79、缺 2 项及以上 91**。

三条校正：

1. **X1 的杠杆比文档估计的更大。** 单独卡住 55 张，涉及 123 张。
   它不是「B/C 的前提」，而是唯一一项动一下就能让 31% 的卡进入「只差一项」的能力。
   M2 的第一块必须只做 X1，不要和系数平面绑在一起做——否则这项收益要等到整个平面完成才兑现。
2. **M3 的顺序要改。** 缺 2 项的组合分布是 X1+X7 **17**、X1+X9 **9**、X1+X2 **8**、X1+X11 **6**，
   而文档里排在前面的 X8 只涉及 3 张、X3 涉及 6 张。建议
   **X7 → X9 → X2 → X11 → X3 → X8**。X9（家族）在 §2 里是 ❌，
   但它同时是 M5 的内容，提前做不会白做。
3. **M4 内部先做 X5。** X5 单独卡 8 张（仅次于 X1），X13 / X4 各 5 张。
   X5 的范围/阈值/上限又是「增益类」卡（绿色革命那一类）的前置，边际收益最高。

审计本身的局限，写在这里免得被当成全量结论：

- 只统计**显式写出来的**能力代号。`B（L3 C）` 这种把升级需求写在括号里的，按 L1 处理、
  不计入阻塞（否则每张引擎卡都会被算成缺 2 项）。
- 卡表里没写能力代号的卡，只能按级别字母的基线推断（B/C → X1，D → X4/X5/X6 任一）。
- 所以「缺 2 项及以上 91」是**下界**，不是精确值。

## 7. 不建议做的事

- **继续给 `FAMILY_METRIC_COUNT` 加 id。** 它已经是 68，每个实例的 slab 和每次采样都会跟着变大。新能力一律走派生列或国家标量。
- **用 Modifier 的非 SUM 聚合去做理念叠加或上限。** 原因见 P2-A。
- **为了去掉 32 上限而调大 `SELECTOR_MAX_CELLS`。** 实例数和 ACK 会线性膨胀，应该走系数平面，见 Doc 03。
- **在 Effect 共享模板上做按国家的参数。** 会串国。
- **在理念侧每天轮询全图。** 任何「每天扫一遍」的实现，都会违反空闲计数器必须为 0 的门槛。
