## 1. M5-17 的阻塞是什么

上一轮负向对照两次失败，最后打印出：

```
[B5] add BEFORE override = 0.14991760253906
[B5] add AFTER  override = 0.14991760253906
```

我把 metric override 设成 **40**，而卡片程序是 `min(metric, 15) × 655 / Q16`。
`min(40, 15) = 15` —— **40 和「更大的值」在钳位后完全一样，内容根本没被我改变**。

于是「generation 没变」是**正确的**（§I13：内容相同不安装、不 bump），而我的对照本身无效。

## 2. 修法：把对照值放到钳位**之下**

改成 `5 × Q16`（oracle 里已证明有效）：

```
[B5] add BEFORE override = 0.14991760253906
[B5] add AFTER  override = 0.04997253417969   gen=2 sample_day=1
```

| 观察 | 含义 |
|---|---|
| `0.1499 → 0.0499` | 内容**真的**变了 |
| `gen 1 → 2` | **负向对照成立**：内容变化确实 bump 版本 |
| `sample_day 0 → 1` | front 真的被重建了 |

## 3. 空闲 30 天：零版本推进

```
[B5] after content change: gen=2 steps=15
[B5] after 30 idle days:   gen=2 (was 2)  steps=17 (was 15)  cells=400 pending=false
```

| 断言 | 结果 |
|---|---|
| `layer_generation` 在 30 天空闲中不动 | **2 → 2** ✓ |
| `sample_day` 冻结（没有重建）| ✓ |
| `derived_rebuild_pending` 保持 false | ✓ |
| 层仍安装、仍覆盖 400 格 | ✓ |
| 贡献仍在（`derived_add = 0.0499`）| ✓（空闲不等于拆掉）|
| 负向对照：内容变化必须 bump | **1 → 2** ✓ |

## 4. 一个我差点用错的量

`cell_layer_rebuild_steps` 最初的断言是「空闲时不增长」，但实测它在多次运行间是
**16 → 14 → 15 → 13 → 17** —— **不是累积计数**。

用它写断言会在噪声上随机失败。换成 `sample_day`：它记录「当前安装的 front 是从哪一天建的」，
**没有重建就完全不动**，这才是这个门禁需要的信号。

**教训：一个计数器如果是「本次运行的步数」，它就不能表达「累计做了多少工作」。**
