## C++ cell-range 重构设计核验（用户「讲讲你会怎么重构 C++ cell-range」）
- 当读 world_ext_physical.cpp 后修正：`run_physical_solve_pass`(1223) 是 SLP→wind→PSI→upwelling 的**一次性**编排，但 GDScript `_physical_solve_step_one` 实际**逐 stage 调** `run_slp_field_pass`(1506)/`run_wind_field_pass`(213)/`run_psi_solver_pass`(2062)/`run_physical_circulation_pass`(1333) —— cell-range 应加在这四个 leaf pass，而非 monolithic 函数。
- **关键反直觉结论**：对 phys 阶段，cell-range 切片**单独不足以压帧尖峰**。证据：phys_psi_init 1.76ms 中 C++ kernel 仅 0.4ms（PSI iter loop 2390-2422，域为 water 子集 n_water），剩余 ~1.3ms 是**每调用固定开销**（GDExtension 边界 + C++ 内 `component_id(StringName(...))` 每 pass 重复 7~13 次 + `is_water_lut` 每调用 256 重建 + 25 字段 knob 解包）。切片只摊 kernel 部分 → 每切片调用仍 ~1.5ms（固定开销不变），尖峰不降反因多次 marshaling 略增总耗时。对比光栅 `run_ocean_field_rasterize`(866 已支持 start_idx/end_idx) 有效，是因为其热点（per-pixel 计算 4.7ms）是 kernel 主导、固定开销占比小。
- **真正的两段式重构**：① 先砍每调用固定开销（缓存 sid_* = component_id(StringName) 到成员、缓存 is_water_lut、缓存静态拓扑/邻居映射进成员，仿 PSI 的 `_psi_cell_to_water/_psi_nb_w` FNV-1a 指纹缓存 2228-2278）；② 在其上才加 `start_idx/end_idx`，此时切片才能把尖峰从 ~1.5ms 真压到 <1ms（因固定开销已近 0）。
- 四 pass 各自约束：SLP 有 `smooth_passes` 邻居扩散(1544) → 切片需 2-cell halo 重叠或拆末期独立 smoothing；WIND 的 coast BFS(338-394)+sea BFS(396+) 是**全局状态须抽出**成一次性 `run_wind_coast_precompute` 或成员缓存；PSI 迭代域已是 water 子集(2392)、warm-start 读 `cell_ocean_psi` slot(2213) 天然跨 tick 持久 → 切片最干净，但 **finalize(grad psi→ocean_current, 2424+) 须加 end_k==n_water 守卫只跑一次**；UPWELLING 最省事（per-cell 独立，仅 is_water_lut）。
- 跨 tick 状态须进 DCWorldExt 成员：coast_dist/sea_dist（wind BFS，新，带拓扑指纹）、cell_ocean_psi slot（复用为 PSI 工作缓冲）、SLP 切片建议直接发布 `cell_slp` slot 供 WIND 读（替代 slp_out 数组 marshaling）。stage 内 cell cursor 放 GDScript 状态机（加 `_phys_cell_cursor`）。
- **本环境无法落地**（需 rebuild DLL + headless PROBE 验证 bit-equal + fallback=0 + p95/max<1ms），只给设计。且此方案仅覆盖 ocean_currents(32.5%)；native_daily_sim(51.5%) 是另一套 `run_native_daily_slice` 节点粒度，不在内，须另走节点切片/步长。
