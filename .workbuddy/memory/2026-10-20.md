### 关键坑（下次直接用）

- **typed array**：`@export var xs: Array[Resource]` 赋值时不能给无类型 `Array`，
  会 `Invalid assignment of property ... with value of type 'Array'`。
  必须先 `var tmp: Array[Resource] = [...]` 再赋。`PackedStringArray` 同理。
- **参数先于函数体求值**：把惰性初始化写在被调函数里，第一个 caller 拿到的是 null。
  测试里必须在 `_run()` 顶部就建好夹具。
- **`String.replace("%s", v, true)` 会替换全部**，多占位符模板必须用
  `find("%s")` + `substr` 手工替换一个 —— 否则所有槽位都填成第一个值。
- **Grep 工具在本仓会因坏符号链接/权限报错退出**（`assets/textures/terrain_materials/*.png`
  拒绝访问、`m7ect/` 悬空路径）。只能限定 `path` 到 `scripts/` 或 `gdext/src/`，
  或改用 bash `grep -rn --include=*.gd`。
- 文档里提到的 **`DEAD_STAT_KEYS` 常量在仓库里根本不存在**，死键此前零校验。

## 第三轮：核查六条红灯 + 阻塞点 D 的根因（只查不改）

### D 的根因不是引擎限制，是 fixture 少等一帧（已实测）

`world_runtime_host.gd:667` 的 `if not is_inside_tree(): return` 是**表象**。
在 `extends SceneTree` 的测试里，`_init()` 阶段 `get_root().add_child(host)` 之后
`host.is_inside_tree()` **仍然是 false**；`await process_frame` 之后才变 true。

实测对比（同一个探针，只差一行 `await process_frame`）：

| | in_tree | map | generator |
|---|---|---|---|
| 不等帧 | false | null | null |
| 等一帧 | true | 非 null | 非 null，DataCore 绑定成功 |

所以 `generate_world` 是**静默返回**，调用方只看到「generator 为 null」。
修法：add_child 之后 `await process_frame` 再 configure/generate。
**注意**：`climate_authority_test` 已经 add_child 但没等帧，所以它也是失败的。

即使修好，无头下的 test economy bootstrap 仍会失败：
`bootstrap_construction_source_missing`，timber=0 / stone=0（17 个 region 全跳过）。
这是另一件事，会影响完整 parity，但不影响地图生成。

### C1 的实际规模比描述小得多

`native_simulation_host.cpp` 15,907 行，违禁 token 只有：
`godot::` ×35、`#include <godot` ×1，`Dictionary`/`Variant`/`PackedByteArray` **全为 0**。
而那 35 处**全部是日志**：`UtilityFunctions::print/printerr` + `vformat` + `String`。
没有数据结构、没有引擎状态、没有 Variant。

所以不是「22 处跨线程调 Godot API」，而是「35 处日志调用挡在纯文件规则前面」。
修法：一个 Godot-free 的 `pk::log_line(...)`（stderr 或 lock-free ring），机械替换即可。
