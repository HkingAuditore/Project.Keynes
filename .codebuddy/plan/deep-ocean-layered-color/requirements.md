# 需求文档

## 引言

当前世界地图深海区域表现为一片**几乎统一的深蓝色**：虽然浅海 → 中海 → 深海之间已经有 `water_depth_gradient()` 五段渐变（coast / shelf / mid / basin / abyss），以及一层基于 fbm 的 "gyre patch" 低频色斑，但这些变化幅度偏小、彩度偏低，并且**没有与逻辑层已经算好的洋流（`ocean_current_v`）、实时温度（`current_temp`）、纬度（`lat_signed`）、风场（`wind_v`）等气候维度建立关联**——结果就是远洋看起来像一块平整的单色底板，缺少"暖流—冷流"、"热带—极地"、"深渊—大陆架"等海洋学上该有的视觉层次。

本功能目标是在 **不新增 atlas 通道、不修改 `MapGenerator` 数据结构** 的前提下，把已经存在于 shader 中的这些维度（深度、离岸度、洋流向量、实时温度、纬度、低频噪声）组合到一起，让深海呈现出**有冷暖差、有洋流走势、有极地 / 赤道差异、有深渊幽冷感**的丰富色彩层次；同时保持整体画面宁静、不抢戏，并完整兼容已有的 `water_cartoon_color_strength` / `visual_quality` / 季节系统 / 湖泊 / 礁石 / 海草 / 海冰等层。

本轮**只改 `world_map.gdshader` 开放海洋分支**（及其所依赖的 `water_depth_gradient`、gyre patch、深海色变调整层），不触碰湖泊 / 河流 / 海岸 / 礁石 / 海草 / 海冰的既有视觉语言。

---

## 需求

### 需求 1

**用户故事：** 作为一名玩家，我希望远洋深海不再是一整块深蓝色，而能在海盆范围内呈现丰富、柔和、像水彩地图一样的颜色层次，以便整张世界地图看起来更像一个有生命的星球。

#### 验收标准

1. WHEN 玩家查看大片开放海域 THEN 系统 SHALL 让深海范围内至少体现"大陆架冷色 → 深海暖蓝 → 深渊冷紫"三种可辨识色调，且相互之间通过连续渐变衔接，不出现生硬色带。
2. WHEN 玩家在同一海盆内横向扫视 THEN 系统 SHALL 通过低频色斑让不同位置呈现略有差异的色温与饱和度，避免大面积纯色。
3. IF `water_cartoon_color_strength` 被降到 0 THEN 系统 SHALL 退化到接近等高线设色的基础深海色，但仍保留深度方向的三段渐变。
4. WHEN 玩家查看截图中的右侧深海区 THEN 系统 SHALL 能明显区分"靠近大陆的半封闭海域"与"开放大洋腹地"两种色感。
5. IF `visual_quality == 0` THEN 系统 SHALL 仅保留主要深度渐变与一层低频色斑，关闭所有依赖时间动画的色彩层。

### 需求 2

**用户故事：** 作为一名玩家，我希望深海颜色能反映洋流的冷暖走势，以便暖流经过的区域看起来更暖蓝 / 偏绿，冷流区域看起来更冷青 / 偏紫。

#### 验收标准

1. WHEN 深海 cell 存在洋流向量 (`ocean_current_v`) THEN 系统 SHALL 根据洋流**流向与纬度的相对关系**（例如 "从低纬流向高纬" 视作暖流，"从高纬流向低纬" 视作冷流）为水色叠加轻微的暖色/冷色偏移。
2. WHEN 洋流长度接近 0 THEN 系统 SHALL 不对水色施加暖/冷偏移，保持该格为对应纬度的中性深海色，避免无洋流区域出现错误色偏。
3. WHEN 洋流强度较大 THEN 系统 SHALL 让暖/冷偏移更明显，但整体振幅受统一上限控制，**不得超过深海主色亮度或饱和度的约 ±15%**。
4. IF `ocean_current_enabled` 为关闭状态 THEN 系统 SHALL 禁用洋流驱动的色偏，仅保留深度 / 纬度 / 低频噪声带来的层次。
5. WHEN 洋流方向与已有的流纹可视化层叠加 THEN 系统 SHALL 保证流纹仍然可见，且色偏不覆盖流纹的亮暗条纹。

### 需求 3

**用户故事：** 作为一名玩家，我希望深海颜色能反映纬度/温度带，以便热带海洋更偏宝石蓝绿、温带海洋更偏中性蓝、极地海洋更偏冷青或近白。

#### 验收标准

1. WHEN 深海处于低纬度（`|lat_signed|` 较小）且 `current_temp` 较高 THEN 系统 SHALL 让水色朝偏绿松石 / 宝石蓝方向轻微偏移。
2. WHEN 深海处于高纬度且 `current_temp` 较低 THEN 系统 SHALL 让水色朝冷青 / 偏灰偏白方向轻微偏移，但**不得伪装成海冰**，海冰仍由 `SEA_ICE` 分支独立控制。
3. WHEN 同一海域跨越多个纬度 THEN 系统 SHALL 使纬度色偏为连续渐变，不出现"某一行突然变色"的水平条纹。
4. WHEN 季节切换导致 `current_temp` 发生变化 THEN 系统 SHALL 让深海色偏随之缓慢变化（如夏季海面略暖、冬季略冷），且不得与植被 / 雪盖的季节语言冲突。
5. IF `season_temp_amp` 或相关季节开关被关闭 THEN 系统 SHALL 退化为仅基于纬度的静态温度色偏。

### 需求 4

**用户故事：** 作为一名玩家，我希望深渊（最深的开放大洋腹地）能呈现更幽冷、更压低明度的质感，以便在视觉上区别于大陆架和中层海。

#### 验收标准

1. WHEN 水体的离岸度 + 深度综合值接近最大 THEN 系统 SHALL 让水色在"basin → abyss"段压低亮度、微微提升蓝紫色彩倾向，表现幽深。
2. WHEN 深渊色被施加 THEN 系统 SHALL 依然保持足够可辨识的蓝调，不得让深海看起来接近黑色或明显发紫过度。
3. IF `deep_ocean_contrast` 参数被调高 THEN 系统 SHALL 让深渊与大陆架之间的明度差更明显；调低则趋于柔和统一。
4. WHEN 深渊区域与开放海的 gyre 色斑、洋流色偏、纬度色偏同时存在 THEN 系统 SHALL 保证这些层的总体叠加不会造成局部过曝或明度断崖。
5. WHEN 深渊边缘过渡到中层海 THEN 系统 SHALL 使用 smoothstep / 权重曲线进行柔和衔接，不出现明显的同心圆边界。

### 需求 5

**用户故事：** 作为一名玩家，我希望深海的丰富色彩不会让海岸、湖泊、河流、礁石、海草、海冰等近岸 / 特殊水体的现有辨识度受到干扰。

#### 验收标准

1. WHEN 深海色彩分层被启用 THEN 系统 SHALL 仅对"开放海洋" 权重（`open_ocean_w` 或等效离岸度 mask）为主的像素生效，浅海 / 海岸区域保持既有色调不变。
2. WHEN 近岸有礁石 / 海草 / 海冰 THEN 系统 SHALL 优先保留它们原有的特征色与叠加顺序，不让新增的深海色偏污染特征色。
3. WHEN 湖泊与深海同屏出现 THEN 系统 SHALL 使两者色调保持当前已有的区分度，不得因"深海更花"而让湖水显得单调或被吃色。
4. IF 水体边界 `water_biome_blend_radius` 较大 THEN 系统 SHALL 让深海新色彩仍然在边界软过渡区内平滑衰减，避免在交界形成硬色环。
5. WHEN 玩家在低配设置下运行 THEN 系统 SHALL 降级后仍保留一套"静态版"的深海色彩分层，不会回退成纯色海面。

### 需求 6

**用户故事：** 作为一名开发者 / 美术，我希望深海色彩增强拥有独立可调参数，以便快速开关、回退或在不同世界预设下微调。

#### 验收标准

1. WHEN 新增深海色彩增强层时 THEN 系统 SHALL 引入一个顶层总强度 uniform（如 `deep_ocean_color_richness : hint_range(0.0, 1.0)`），默认值对截图场景有明显可见改善。
2. IF 该强度被设为 0 THEN 系统 SHALL 完全还原为当前（本需求实施前）的深海色彩表现，不留任何视觉残留。
3. WHEN 需要单独隔离洋流色偏、纬度色偏、深渊压暗、gyre 增强等子层 THEN 系统 SHALL 以子强度或布尔开关形式提供独立控制（可叠加于总开关之上）。
4. WHEN 新增 uniform 写入 shader THEN 系统 SHALL 保持现有 `.tscn` / `HexRenderer` 的参数兼容，**不重命名或删除**已有水体参数。
5. IF 某个依赖（如洋流 atlas、纬度解码）数据缺失 THEN 系统 SHALL 安全回退到不生效的分支，不引发渲染异常或整片海面变色。

### 需求 7

**用户故事：** 作为一名开发者，我希望深海色彩优化不会显著增加每像素开销或打破 `visual_quality` 分级，以便在所有档位都保持流畅。

#### 验收标准

1. WHEN 渲染一帧世界地图 THEN 系统 SHALL 不因本轮改动在 fragment shader 中引入超过约 2 次额外 fbm 或 voronoi 调用。
2. WHEN `visual_quality == 0` THEN 系统 SHALL 仅保留"深度渐变 + 单层静态色斑 + 纬度色偏"，禁用时间动画与洋流驱动的彩色偏移。
3. WHEN `visual_quality == 1` THEN 系统 SHALL 启用洋流色偏与深渊压暗，但限制任何时间动画频率在现有 gyre 动画档位以内。
4. WHEN `visual_quality == 2` THEN 系统 SHALL 启用全部子层，且允许最柔和的低频动画，仍不得引入高频闪烁。
5. WHEN 本轮代码合并后 THEN 系统 SHALL 通过同一测试地图的目视对比，确认帧时间不显著劣化于上一轮水体重构的基线。

## 关键决策记录（本轮）

| # | 决策点 | 选定方向 | 本轮硬约束 |
|---|--------|----------|-----------|
| 1 | 数据源 | 全部复用现有 shader 内可得的量：`offshore_depth` / `ocean_current_v` / `current_temp` / `lat_signed` / `wind_v` / fbm | 不新增 atlas 通道，不改 `MapBaker` / `MapGenerator` |
| 2 | 作用范围 | 仅对 `open_ocean_w` 显著 (>0.1) 的像素叠加新色彩层 | 近岸 / 湖 / 礁 / 藻 / 冰保持现状 |
| 3 | 总振幅上限 | 三类色偏（洋流暖冷、纬度温度带、深渊幽冷）单独封顶，叠加后整体 < ±20% 明度 / 饱和度 | 禁止出现局部过曝 / 纯紫 / 近黑 |
| 4 | 参数对外 | 新增 `deep_ocean_color_richness` 及少量子开关，兼容现有 `.tscn` | 不重命名已有 uniform |
| 5 | 性能 | 所有新增仅算术 + 至多 1 次新 fbm（与 gyre 共享） | 不引入新的纹理依赖 |
| 6 | 动画 | 暖/冷/纬度偏移为静态或极慢漂移（沿用 world_time * 0.01 量级） | 禁止高频动画 |

## 非目标（本轮显式不做）

- 不新增体积雾 / 水下散射 / 屏幕空间反射
- 不改动湖泊、河流、礁石、海草、海冰、海岸的既有色彩层
- 不改动 `MapGenerator` / `WorldData` / `MapBaker` 的任何数据结构
- 不新增洋流或温度相关的 per-cell 字段
- 不替换 `color_deep_ocean` / `color_mid_ocean` / `color_coast_water` 等等高线基色
- 不改变 SEA_ICE 的生成与表现逻辑

## 风险与开放项

| # | 风险 | 缓解 |
|---|------|------|
| R1 | 多层色偏叠加导致深海整体偏紫 / 偏绿失真 | 在叠加最后对最终 `ocean_col` 做一次向 `color_deep_ocean` 的软回拉 (mix ≤ 0.15) |
| R2 | 洋流向量在离岸衰减区可能抖动 | 使用 `length(ocean_current_v)` 做权重门限，短向量直接不生效 |
| R3 | 纬度色偏与季节温度偏移两套时间源不同步 | 统一由 `current_temp` 计算，而不是直接读 `season_phase` |
| R4 | 新参数命名与未来水体扩展冲突 | 统一以 `deep_ocean_*` 前缀命名，保留扩展空间 |
| R5 | 低配画质下色彩层次消失，观感回到旧状 | 至少保留纬度色偏 + 深度渐变这一条最便宜路径在 `visual_quality == 0` 时仍启用 |
