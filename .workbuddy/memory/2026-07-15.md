# 2026-07-15

## GM 面板新增「经济数据录制」（分维度多文件 + 维度开关）

用户要在 GM 面板（调试控制台 / 玩家 GM 面板共用的 Telemetry 组）录制经济数据，
原只有「开始地块全量录制」（气候 SoA）。采用用户选定的「分维度多文件 + 维度开关」方案。

### 实现
- 新增 `Project/project-keynes/scripts/ui/economy_data_recorder.gd`（class_name EconomyDataRecorder, extends RefCounted）：
  - 触发节奏：每经济 epoch 提交时写一批（用 `world.get_economy_report().epoch_id` 推进检测，非逐 tick）。
  - 产出最多 5 个 CSV（桌面 `../../tmp/economy_record_<ts>_<dim>.csv`，手机 `user://economy_data`）：
    summary / cohorts(阶层) / buildings(建筑) / resources(30 个自然资源 SoA 槽位) / market(物资)。
  - 维度开关 `set_record_*(bool)` + `set_sampling_config(cell_stride, max_rows)`，默认全开。
  - 数据来源：经济快照 API 直接挂在 `DCWorldExt`（`world`=`generator.get_data_core_world_ext()`），
    不走 economy_facade。cohorts/building/market 用 `get_*_cell_snapshot(idx)`；
    resources 用 `world.snapshot_f32(world.component_id("cell_res_<mid>_reserve"))`（30 个槽位名在脚本常量里，
    启动时按 component_id 解析、缺失跳过）。
  - 只读快照，不改任何经济状态（C++ 仍为唯一权威）。
- `main.gd`：加 `_economy_data_recorder` 变量 + `set/get_economy_data_recorder`；
  在 `_publish_fast_tick_perf_sample` 内（与 perf/tile 录制并列）调用 `on_fast_tick` 并把
  `economy_ms/recorded/rows/reason/epoch_id` 并入 recorder perf summary。
- `debug_console.gd`：preload `EconomyDataRecorderScript`；`set_main` 内实例化并 `bind_main` + 注入 main；
  Telemetry 组新增 5 个维度 CheckBox（汇总/阶层/建筑/自然资源/物资，默认勾选）+ 「⏺ 开始经济录制」按钮
  （回调 `_on_btn_toggle_economy_record`，停止时返回导出路径数组）。两处面板均可见。

### 修复（用户本地报 Parser Error 后）
- `SUMMARY_COLUMNS` 等 5 个列常量初值误用 `PackedStringArray([...])` 构造函数调用，GDScript `const` 不允许
  非字面量初值，报 "Assigned value for constant 'SUMMARY_COLUMNS' isn't a constant expression"。
  已全部改为纯数组字面量 `= [...]`（与 SUMMARY_FIELDS 一致）。
- `_format_summary_line` 残留 `])` 括号不匹配（移除 `_concat` 助手时遗留），已改为 `]`。
- **二次坑（用户报 debug_console.gd (60,1) "Closing ')' doesn't have an opening counterpart"）**：
  根因在 `economy_data_recorder.gd`——上一轮把 11 处 `PackedStringArray([` 用 replace_all 改成 `[` 时
  **只改了开头、没改结尾**，导致每个数组变成 `[ ... ])` 多出一个 `)`（10 处 stray `)`：
  5 个列常量 + 5 个 writer 数组的 `])` 收尾）。Godot 通过 `preload` 链把依赖脚本的解析错误
  **错位报到了消费脚本 debug_console.gd 的第 60 行**，极具迷惑性。
  已写 `tmp/fix_stray_paren.py` 用**跨行全局括号栈**精确删除仅"全局栈空时遇到的多余 `)`"，
  保留合法的 `print("..." % [ ... ])`（281/300 行），复验两个文件 PAREN BALANCE OK。
- GDScript 经验：① const 初值必须是纯字面量；② replace_all 改括号配对构造时**首尾都要改**；
  ③ preload 依赖脚本的解析错误会被 Godot 错位报到消费脚本行号，定位时要查依赖方而非只看报错文件名。

### 验收注意
- 本机未 rebuild/跑 Godot 验证（无编辑器运行环境），属设计+编码态；需在编辑器里实际开始录制、
  推进若干经济 epoch 后检查 `tmp/economy_record_*.csv` 列与行数。
- 大地图全开四维度体量很大（resources 30×cell、market good×cell 每 epoch），可用维度开关关掉不需要的，
  或后续加 cell_stride 抽样（已预留 set_sampling_config，但 UI 暂未暴露 cell_stride 控件）。
