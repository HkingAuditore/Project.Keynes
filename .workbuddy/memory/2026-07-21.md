## 投资资本转移守恒漂移（运行时硬暂停 → 改5 投资路由回退）
- **运行时报错**：`economy_daily_system.gd:92 tick(): native economy paused: building_investment_capital_transfer_drift`（C++ 自检 `funds[sponsor] != source_funds_before - required_capital` @7952 触发暂停）。
- **根因（读通 7913-7959 + move_cohort_population@11534）**：投资资本转移逻辑**本质按"owner 是不同于 sponsor 的职业 cohort"设计**——先 `move_cohort_population(sponsor, cell, target_signature, 1)` 把 1 人从 sponsor 移到业主职业 cohort，人携带人均资金 `carried`，再用 `correction=required_capital-carried` 补足/退还，7952 校验 `funds[sponsor]` 净减 `required_capital`。我改5 把 `candidate.target_signature` 从 `target_signature`(业主职业, 7791) 改成 `owner_signature=signature_id[sponsor]`，使 `move` 退化成同 cohort 移动 → `carried` 错乱 → 守恒漂移。
- **关键认知更正**：原投资路径**本就实现"有钱即转职"**——`target_signature=业主职业` + `move_cohort_population` 把 sponsor 的 1 人转职进业主职业 cohort（sponsor 可跨职业，find_entrepreneur_source 要求 source.prof!=target.pro 且同 eth）。真正需去掉的硬绑定是**手动建造门**(4783)，已删。改5 的投资路由覆盖既多余又破坏守恒。
- **修复=回退** economy_runtime.cpp：
  - 删 `const int32_t owner_signature = _population.signature_id[sponsor];`(7851) 及注释。
  - `candidate.target_signature = owner_signature;`(7877) → `candidate.target_signature = target_signature;`
  - 新增注释说明 profession mobility 由手动门+跨职业资本转移承担、候选仍以业主职业为 target。
- **手动建造门(4783)改动保留**：`owner_signature = signature_id[owner_slot]`，任何职业可建/拥有（owner=建造者 cohort），无跨 cohort 资本移动，无漂移风险。
- **验证**：需用户本地 rebuild DLL + 跑 `verify_economy_runtime.ps1`(账本守恒) + 重跑 cell1104，确认不再 paused、炉灶1→2、processed_food 价回落、不超建。
- **教训**：投资资本转移是硬守恒不变量（漂移即全经济暂停），任何改 target_signature/owner 的覆盖必须保持"owner≠sponsor 跨 cohort"假设；改5 当初不该动投资路由，只改手动门即可满足"有钱即转职"。
