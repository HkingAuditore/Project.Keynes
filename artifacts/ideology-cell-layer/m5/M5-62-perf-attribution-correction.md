# M5-62 §14.3 归因纠正：超标发生在「含重建的那一片」，不是每一片

| 项目 | 内容 |
|---|---|
| 触发 | 复核 B3 的 4.96 ms 时发现它的报告字段是**累计最大值**，不能用来说明「每一片都超标」|
| 日期 | 2026-10-28，Asia/Hong_Kong |
| 结论 | **三种场景的准确表述都变了**：稳态每片远低于 1 ms，**含重建的那一片**超 1 ms |

## 1. 我原来的说法（不准确）

前几轮我把 §14.3 写成「超标」，并引用：

| 场景 | 我引用过的数字 |
|---|---|
| 64 国 × 12 卡（B1）| `worst_step_ms = 2.572` |
| 512 国（B3）| `max_slice_ms = 4.96` |
| 超大国家 kind 14/15 | ≈2.19 ms |

## 2. 复核时发现的语义问题

```cpp
// ideology_runtime.cpp
_max_slice_ms = std::max(_max_slice_ms, _last_slice_ms);   // :4901 累计，从不重置
_cell_layer_rebuild_ms = std::max(_cell_layer_rebuild_ms, step_ms);   // :7062 累计
_derived_materialise_ms = std::max(_derived_materialise_ms, step_ms); // :7063 累计
```

**三个都是全运行累计最大值**，包含 setup 阶段。而 B3 的日志自证了这一点：

```
day 1: last_slice_ms=0.2579  max_slice_ms=4.9644  materialise_ms=1.5795
day 2: last_slice_ms=0.2665  max_slice_ms=4.9644  materialise_ms=1.7083
```

- `max_slice_ms` 两天**完全相同** → 峰值在 day 1 或之前就已达到
- `materialise_ms` 从 1.5795 **长到** 1.7083 → **day 2 内确实出现过 1.7083 ms 的重建步**
- 而 day 2 的 `last_slice_ms` 只有 **0.2665 ms**

## 3. 准确的表述

| 量 | 准确说法 |
|---|---|
| 512 国的**稳态每片** | **0.2579 / 0.2665 ms** —— **低于 1 ms** |
| **含重建的那一片** | **≈1.71 ms**（day 2 内实测）—— **超过 1 ms** |
| 4.96 ms 的那一片 | 在 **day 1 或更早**；从现有字段**无法归因**到稳态遍历（`active_progress` 仅 0.015–0.029 ms，`transition_poll` 0.12–0.21 ms）|
| 国家遍历本身 | **0.015–0.029 ms** —— 完全不是成本所在 |

**所以正确的结论是：**

> 512 国 × 9 片的理念日里，**8 片约 0.26 ms、1 片（含重建）约 1.7 ms**。
> §14.3 的「单 slice ≤ 1 ms」**被那一片突破**，但不是「每一片都突破」。

这与「512 国一天 4.96 ms」是完全不同的严重性判断。

## 4. 对三个场景的统一说法

| 场景 | 稳态每片 | 含重建的那一片 | 判定 |
|---|---:|---:|---|
| 512 国（B3，1024 格） | **0.26 ms** | **1.71 ms** | 重建片超 1 ms |
| 64 国 × 12 卡（B1，512 格） | 未单独测 | **2.57 ms**（累计最大，可能在装备轮次中）| 超 1 ms |
| 超大国家 kind 14/15（6400 格）| — | ≈2.19 ms（**外推，未实测**）| 超 1 ms |

`DERIVED_REBUILD_STEP_BUDGET_MS = 0.45 ms`：**三种场景的重建步都超过这个预算**，这一点是确定的。

## 5. 我没有做的事

- **没有改 `max_slice_ms` 的语义**。它是累计最大值，这是合理的报告口径（「本次运行最坏一片」）；问题在于我**拿它当成了稳态值**。
- **没有归因 4.96 ms 那一片**。日志里没有逐片明细，我没有去加逐片记录——那需要改代码。
- 没有把这条写成「已达标」。**超 1 ms 仍然成立，只是范围变了。**

## 6. 一条可复用的检查

**报告里的 `max_*`／`worst_*` 字段是累计值，不能用来说明「典型值」。**
要用它判断稳态，必须同时看「最后一次」字段（`last_slice_ms`）或逐次明细。

我这次是看到 `last_slice_ms=0.26` 与 `max_slice_ms=4.96` 相差 19 倍才起疑的——**两个字段相差一个数量级时，通常有一个被误读了**。
