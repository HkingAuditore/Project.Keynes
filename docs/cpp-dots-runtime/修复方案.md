## 阶段 1：修复生产资金、knapping 利用率和 derived demand

主要修改 [economy_runtime_building_production.cpp](D:/Godot/ProjectKeynes/Project.Keynes/gdext/src/economy_runtime_building_production.cpp)、[economy_runtime_market.cpp](D:/Godot/ProjectKeynes/Project.Keynes/gdext/src/economy_runtime_market.cpp) 和 [economy_runtime_building_investment.cpp](D:/Godot/ProjectKeynes/Project.Keynes/gdext/src/economy_runtime_building_investment.cpp)。

### 1. 资金和 Hunter ACTIVE

删除 `run_building_production_cell()` 中固定的 `const int64_t credit_cap = 0`。

信用额度统一按以下公式计算：

```text
merchant_opening_cash =
    sum(max(merchant.funds, 0))

exposure_limit =
    merchant_opening_cash * _merchant_credit_exposure_q16 / Q16_ONE

protected_cash =
    merchant_opening_cash * _merchant_procurement_cash_reserve_q16 / Q16_ONE

cell_credit_remaining =
    max(0,
        min(exposure_limit - outstanding_principal,
            merchant_opening_cash - protected_cash))
```

每个 building group 的可用额度为：

```text
group_credit_cap =
    min(cell_credit_remaining,
        max(0, group_requested_credit_cap))
```

默认继续使用当前配置：

- merchant credit mode：`ACTIVE = 2`；
- exposure：`25%`；
- merchant cash reserve：`12.5%`；
- premium：`5%`；
- term：`6` 个 settlement cycles。

Hunter、collector 和其他生计生产者在资金不足时：

- 先使用 owner 现金；
- 再从 merchant-backed credit reservation 借款；
- 借款写入 `merchant_debt_principal`、`merchant_debt_premium`、`merchant_debt_term_cycles_left`；
- 记录 `CASHFLOW_MERCHANT_BUSINESS`；
- 产生结构化 `FINANCE_DRAW` event；
- 不因短期现金不足改变 `operating_state`；
- 不因“无法融资”增加 severe-loss counter；
- 只有连续结算周期的真实已实现亏损才能进入 `SUSPENDED_LOSS`。

如果 credit 也耗尽，building 仍保持 `ACTIVE`，保留 bounded purchase intent，并在下一 review 重试。物理投入完全不可执行时可以产出为零，但必须记录 `ACTIVE_UNFUNDED`，不能把该状态伪装成 suspended。

### 2. Business shortage 和 knapping floor

真实 business demand 拆成三个独立量：

```text
desired_business_demand
funded_business_demand
unfunded_business_demand
```

对于 knapping 等 durable industrial output：

```text
industrial_probe_floor = Q16_ONE / 32
```

对于 cycle-flow output：

```text
industrial_probe_floor = Q16_ONE / 6
```

计划阶段：

```text
planned_utilization =
    max(configured_probe_floor,
        survival_floor,
        current_business_intent_floor)
```

如果库存、资源和资金允许，`funded_capacity_q16` 不得低于该 floor。

如果硬投入或资金不足：

- `purchase_intent_capacity_q16` 仍保留 probe floor；
- 缺口进入 `unfunded_business_demand`；
- 未满足部分进入下一周期 `business_demand_ema`；
- 不支付不存在的工资；
- 不凭空生成产出；
- 不创建只由 derived demand 造成的 owner vacancy。

输入候选、数量、价格和 reservation 必须在 quote 阶段一次确定，commit 直接使用 quote 结果。

### 3. Derived demand 隔离

`refresh_derived_business_demand()` 只根据冻结的真实 demand snapshot 做一跳 Leontief 传播，并增加：

```text
derived_snapshot_generation
derived_snapshot_hash
derived_demand_by_good
derived_pressure_by_good
```

严格区分：

- `real_business_demand`：可以采购、扣库存、生产、销售、填 owner；
- `shadow_derived_demand`：只能影响价格压力、投资排序和上游机会信号。

shadow derived demand 禁止：

- 填充 vacant knapping；
- 创建 owner；
- 创建 employee；
- 扣库存；
- 产生销售；
- 写入真实 business EMA；
- 触发普通 building construction commit。

`market_flow_deficit_daily()`、`price_pressure()` 和投资 review 必须读取同一个 frozen snapshot。价格压力使用：

```text
price_pressure_input =
    real_shortage_pressure
    + derived_weight_q16 * shadow_derived_pressure / Q16_ONE
```

shadow demand 只增加价格压力，不改变实际 stock flow。

flint 验收场景要求：

- flint 有 derived demand；
- 没有对应 shadow 采购；
- flint stock 不因 derived demand 被扣减；
- 在未触及 catalog ceiling 时，flint price 下一结算周期严格上升；
- 结构化证据中同时出现 `derived_pressure_q16 > 0` 和 `price_delta > 0`。

阶段门槛：#1、#2、#3、#4 fixture 通过，账本守恒，未出现 shadow demand 造成真实 vacancy 或库存变化。

## 阶段 2：重构就业 reservation/commit 和 owner mobility

主要修改 [economy_runtime_building_employment.cpp](D:/Godot/ProjectKeynes/Project.Keynes/gdext/src/economy_runtime_building_employment.cpp)。

就业流程固定为：

```text
冻结 source/target/capacity/income
→ unemployed hiring
→ same-profession owner fill reallocation
→ owner-to-owner profession change
→ employee-to-owner promotion
→ employee job-to-job
→ deterministic commit
```

每个 source、target group 每个 employment period 最多参与一次。所有候选按：

```text
cell
group index
profession
source handle
target group
role
```

稳定排序。

### 1. settled income

owner mobility 和 employee→owner 的收益只能读取上一 committed cycle 的 settled 字段：

```text
last_market_receipt
last_in_kind_livelihood_value
last_input_cost
last_base_wages_paid
last_maintenance_cost
last_business_tax_paid
owner living cost
```

不得读取当前尚未提交的 speculative revenue、当前 quote 或 shadow derived demand。

### 2. High-income food building 吸引 mining employee

当 food building 有真实 owner vacancy 时：

- 先尝试 unemployed owner；
- 没有合格 unemployed owner 时，检查同民族 employee source；
- `target_owner_income` 必须至少高于 source employee after-tax income `12.5%`；
- source employee 和 target owner 必须均有有效 signature；
- 预留 source employee、target owner slot 和 population move；
- commit 时只调用一次 `move_cohort_population()`；
- 同时减少 employee fill、增加 owner fill；
- 更新 source/target cohort employment counters；
- 任一步失败则整体 rollback。

该路径不得被普通 owner source 缺失阻断。

### 3. Surplus merchant 转为其他 owner

merchant owner 可以转换到其他 owner profession，但 commit 前必须满足：

```text
living_merchant_population_after_move >= 1
```

因此：

- 本地有两个或更多 merchant 时允许转出 surplus merchant；
- 本地只有最后一个 merchant 时拒绝；
- 拒绝原因固定为 `LAST_MERCHANT_PROTECTED`；
- 该拒绝不能减少 merchant population、owner fill 或 funds。

### 4. Same-profession owner mobility

source 和 target profession 相同时，只允许：

```text
source_group.filled_owner -= take
target_group.filled_owner += take
```

禁止：

- `move_cohort_population()`；
- 改变 profession；
- 改变 cohort population；
- 改变 owner/employee employment counters；
- 改变 cohort funds；
- 改变 merchant population；
- 改变 owner signature。

该路径只重分配 building owner fill。

### 5. Understaffed hysteresis

保持现有基础 hurdle `12.5%`。当 source 和 target 都 understaffed 时：

```text
effective_hurdle =
    2.0 * base_hurdle
```

并增加持久 cooldown：

```text
cooldown = 30 simulation days
```

cooldown 写入 authoritative owner mobility side table，并进入 state hash/ECP2。cooldown 未到期时，反向迁移直接拒绝。只有收益改善达到 `25%` 且 cooldown 到期后，才允许反向移动。

阶段门槛：#5、#6、#7、#8 fixture 通过；同 profession 场景 population/funds/counters hash 保持不变；understaffed owner 不再因小收益来回迁移。

## 阶段 3：incumbent displacement 和失业 catch-up

主要修改 [economy_runtime_building_investment.cpp](D:/Godot/ProjectKeynes/Project.Keynes/gdext/src/economy_runtime_building_investment.cpp)。

### 1. 持久 incumbent side table

每次 `AGGREGATE_PUBLISH` 成功后，按稳定 `(cell, output_good, type_id)` 保存上一 committed cycle 的 incumbent：

```text
incumbent identity
building type
cell
output good
settled unit cost
daily offered capacity
owner fill
employee fill
settled day
generation
stealable capacity
```

`last_*` 工作字段只用于当前周期诊断，不能再作为 displacement 的历史依据。

settled unit cost 固定为：

```text
(input cost
 + base wages
 + maintenance
 + owner livelihood
 - in-kind livelihood)
 / realized output
```

单位和舍入必须与生产结算完全相同。

### 2. 低成本 challenger displacement

只有以下条件全部满足才允许 displacement：

- challenger 已解锁；
- challenger 有真实 demand 或 catch-up startup reserve；
- challenger `settled_unit_cost < incumbent.settled_unit_cost`；
- 差值至少一个最小可表示货币单位；
- challenger 材料、资源、owner、employee 和 credit reservation 全部成功；
- incumbent 有足够 `stealable_capacity`。

成本相同或更高时保留 incumbent。challenger commit 失败时，incumbent 的 settled fill 和状态完全恢复。

### 3. 高失业率 catch-up

定义：

```text
unemployment_ratio =
    unemployed_population / labor_force_population
```

当日开始时 `unemployment_ratio > 25%` 即进入 catch-up。catch-up lane 独立于普通 investment 的：

- margin；
- payback；
- sponsor capital；
- ordinary probability；
- owner profitability。

catch-up 使用 merchant-backed startup reserve，仍受：

- 技术解锁；
- 真实材料；
- 真实资源；
- owner population；
- merchant exposure；
- ledger reservation；

约束。

优先级固定为：

```text
已有建筑空缺
→ 已安装但 suspended 的可恢复建筑
→ 最低 settled unit cost 的已解锁 industrial building
→ cell index/type id 稳定排序
```

每个 catch-up reservation 预留：

```text
30-day input cost
30-day wages
30-day owner livelihood
construction/material cost
credit principal and premium
```

验收硬条件：

- 触发日起 30 天内至少一个 catch-up job 进入 `ACTIVE`；
- 只要 unemployment ratio 仍高于 25%，每个 30-day review 必须有实际 jobs started；
- 365 天内 unemployment ratio <25%；
- credit principal、premium、工资、投入、产出和人口迁移全部守恒；
- catch-up 不得制造只由 shadow derived demand 产生的 vacant owner。

阶段门槛：#9、#10、#11 fixture 通过，incumbent displacement 和 catch-up 均可恢复、可审计。
