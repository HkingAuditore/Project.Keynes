# 文案 / 内容 / 布局 / 图形化 / 数据展现

## 1. 玩家文案

写成 cabinet brief：先给结论，再给数据；回答「是什么 / 现在怎样 / 有何风险 / 能做什么」。标签要短，不写括号讲座。

```
好：湿度 51% · 基线 42%
坏：当前湿度：0.51（湿润） 年均基线：0.42（含长期湿润反馈）
```

**禁止词表（玩家可见字符串）**

| 类别 | 词 |
|---|---|
| 实现术语 | 原生、runtime、Q16、定点、MarketStore、tick、fast_tick、p95、SUS、worker、POD、snapshot、探针、冻结、中性环境、修订、揭示证据、硬前置、安全边界、autoload、SoA、运行时尚未就绪 |
| 内部标识 | `pk_` `PK` `gm_` `perf_` 前缀、`res://` 路径、类名、文件名、v1/v2 版本号、存档格式号 `PKSV` |
| 测试 / 临时 | 测试、test、debug、TODO、FIXME、临时、占位、placeholder、dummy、mock、示例、样例、生成测试经济数据 |
| 内部量纲 | 百人日、每百人日、每百人、`/百人`、万人日、千人日、`1/10000`、`1/1000`、`1/65536`、缩放因子、原始单位、原值、量纲 |

**单位口径**：玩家侧流量统一写「/ 人·日」（或「每人每日」），配备量写「每人 N 件」。中文数字一律 `UITokens.format_compact_number_cn()`。同一指标在不同界面必须用同一单位与口径；`百分点` 与 `%` 不可混用。

**边界（要保留，别误删）**：单位标注、禁用原因、后果提示（如「次日生效」）、量程端点数值、`reason` 字段。2026-11-05 复核 421 条命中后判定 42 条属必要信息。

## 2. 内容取舍：禁止无用信息

两类最容易复发，都来自「想让界面更清楚，结果又塞了一行说明」：

**P22 自证性 / 脚注式说明** —— 给图形或单位写「它是怎么算出来的」。禁止：
- 「战力 · 条长按当前兵种集归一」（2026-11-05 用户点名删除）
- 「人均 GDP：年度 GDP ÷ 全国人口；与年度 GDP 同口径（读数前的金币图标即单位）」（`era_indicator_view_model.gd:14`）
- 「原始年度账目（金额单位为 1/10000 游戏货币…）」（`annual_report_view_model.gd:227`，还叠加了内部量纲外泄）
- 一切「按…归一」「口径」「基准为」「注：」「说明：」「计算方式」「仅供参考」「示意」

**正确做法是用设计替代说明**：兵种卡把条长改为三项数值之间相对比较（`top = max(攻击, 防御, 机动)`），并排即自明，不暴露归一化分母；卡片高度 258px → 214px。

**P23 空态套话 / 零信息行** —— 禁止 `无需…`、`暂无…`、`不计`、`—`、`读取中…`、`待结算`（边界）、`尚未就绪`、`暂不可用`、空占位 Label、为不存在的东西保留 section title 或固定高度容器。

**正确做法是空即不渲染**：`supply` 为空时整节不加任何子节点，不写「维护物资 无需额外消耗」，也不保留一行灰字。删文案时连同承载它的容器 / section title / `custom_minimum_size` 一起删，不要只把文字清空留一个空 Label。

真实反例：
- `family_workspace.gd:1659` `_add_empty_label` 给一行字强制 `Vector2(0, 56)`，8 处调用各留白 56px（改一行修一批）。
- `scenes/main.tscn:208` 12 个字段全是 `XXX：—`，唯天气写死「晴朗」假读数。
- `scenes/ui/papercut_map_preview.tscn` 与 `land_layout_card.tscn` 写死「两个大陆 · 海平面 50%」示例数据。

## 3. 布局

- 按**玩家决策 / 因果 / 时间 / 量级 / 对比**排字段，不按原生枚举、代码模块、字母序。2026-11-05 用 93 字段矩阵量化：决策覆盖率 44.4%、字段信噪比 41.9%、**顺序合理度仅 5.7%**（5/87 相邻字段对符合因果或时间顺序）。
- 断点 token 必须真正接线。实测 `ui_tokens.gd` 定义了 3 个分辨率断点却全库零引用，实际生效的是 614 处 `separation` 字面量（20 种取值、含负间距）、233 行硬编码字号、878 行 padding、1261 行硬编码坐标 / 固定尺寸（206 文件）。
- 骨架用 Container + anchors，肉尽量别用像素。注意 **Container 自身设全屏锚点是 Godot 标准写法**，不要判成缺陷；真正的问题是「Container 子节点又设 anchor」（实测 0 处）。
- `project.godot` 只有 `window/stretch/aspect="expand"` 而无 `window/stretch/mode`，UI 不随窗口缩放，靠 `mobile_ui_scaling.gd` 手工补丁。`military_workspace.tscn` 固定宽 `392+4×150=992`，在移动 QA 档逻辑宽 930 与 1024×600 桌面窗口都溢出，配合 `clip_contents=true` 会裁掉页签 / 关闭按钮。
- 必检分辨率：1600×960（开发视口）、1280×720、21:9、1024×600、移动 QA 档（`PK_UI_QA_PROFILE="profile=mobile,dpi=440"` 得 logical 930×558）。
- 紧凑度可复算：卡片高度、留白占比、一屏能否同时看见列表与详情。

## 4. 图形化

- 图标 / 色条 / 徽章 / 仪表 / 示意图优先于纯文字表格。构成用堆叠条或环，时间序列用折线，对比用并列条，层级关系用示意而非缩进文字。
- 332 个 `assets/icons/paper` 语义图标必须参与**数据编码**，不是只当装饰。
- 组件造好了必须接线。实测 36 个盘点组件中 **29 个只服务 0~1 个面板**；`radial_gauge.tscn`、`gauge_bar.tscn`、`metric_grid.tscn`、`insight_shell.tscn` **4 个场景组件 0 引用**（脚本里还写着「必须通过 X.tscn 实例化」的校验）；年报 8 个图表全部单点复用、同功能雷达重画两遍。
- 状态 / 枚举（开 / 关、风险等级、趋势、解锁）用 badge 或图形，不只用文字。
- 禁止伪数据条：`military_peer_stats.gd:43` 的「下方短横线」宽度是 `(cell-12)*_grow`（`_grow` 是入场 Tween），**与数值无关、恒等长**。

## 5. 数据展现

**禁止裸数字**：每个玩家可见数值至少带单位、基线、量程、对比、趋势之一。实测 9 类面板 89 个数值位中 54 个（60.7%）仍是文字数字、23 个（25.8%）连单位都没有；国家 / 理念 / 建筑 0% 图形化、HUD 首屏 0%（全在 hover）。

**图表必须有**：轴、刻度、单位、图例、零点基准、量程标注。实测 33 个自绘图表**仅 1 个（3.0%）完全合格**，21 个（63.6%）缺 ≥3 项，11 个（33.3%）按自身 `peak/max/hi` 静默自适应量程却不标注上限（`dossier_trend_lines.gd:70` 等）。根因是两个图表基类没有统一 `draw_axis(min,max,unit,legend)` 与共享量程——修基类，不要逐个补丁。

**其他硬规则**：
- 同屏图表共享量程；自适应量程必须在图上印出上限数值。
- 同一数值同屏只出现一次。反例：`cell_inspector_view_model.gd:1104/1106` 短缺率 gauge 的条上 text 与 hover tooltip 都是同一个 `"%.1f%%"`；`good_dossier` KPI ↔ gauge ↔ tooltip 四重同值；兵种卡页头「编制 25%」+ 成本带「当前编制 25%」。
- 写死数量词 / 槽位数必须与实际数组长度一致。反例：`annual_tax_stack.gd:70` 恒写「五项税收合计」但 VM 过滤零税后色带 1~5 段；`annual_cover_view.gd:174` `for i in 3:` 只建 3 个 KPI 槽而 VM 给 4 项、场景 4 列，第 4 项凭空消失；静默 `slice(0, N)` 截断必须补「另有 N 项」。
- 禁止无数据时伪造读数。反例：`family_workspace.gd:492-500` 用 `prestige_pct * 0.85/0.92/0.95` 伪造人口 / 资金 / 产业份额，还配真实占比 tooltip，与同文件 `:522-523`「不要用 85% 之类的常量把它填满」的注释直接矛盾。
- 「数据已算好但没渲染」是最便宜的修复：VM 里已经有值、组件已有绘制能力，只差一次接线。优先查这类。

## 6. 单位与量纲契约

`100`、`Q16=65536`、`GOODS_SCALE=1000`、`MONEY_SCALE` 都是**作者层缩放因子**（内核全整数，人均 0.0005 件表达不了），不是玩家单位。

- 换算**只在展示层**做：`military_unit_roster.gd` 的 `_per_person()` 把 `wage_per_100` / `supply.value` / `per_100` 除以 100，字段名 `wage_per_100`、`per_100` 保持不变，VM 与原生契约零改动。
- 装备是**配备量（存量）**，不是每日流量，写「每人 N 件」而非「每人每日 N 件」。
- 格式按量级给足有效位：`%.2f` 会把 0.0042 抹成 0.00；小于 0.01 用 4 位。
- 同一份 `report` 不能一边给换算后的 %/金币/件、一边把缩放前整数印进 `full_text`（`annual_report_view_model.gd:230,237` vs `:463-467` 双口径）。

## 7. 量化评估（可复算，用于验收）

| 指标 | 定义 |
|---|---|
| 决策覆盖率 | 界面能完整回答的玩家决策问题数 / 该界面应承担的问题数 |
| 字段信噪比 | 与任一决策相关的字段数 / 首屏总字段数 |
| 顺序合理度 | 按因果 / 时间 / 量级排序的相邻字段对数 / 总相邻字段对数 |
| 数值图形化率 | 被条 / 环 / 仪表 / 折线 / 热格承载的数值位 / 玩家可见数值位 |
| 图表合格率 | 具备轴+刻度+单位+图例+量程的图表数 / 自绘图表总数 |

给出分子分母，不用「感觉更清楚了」当结论。
