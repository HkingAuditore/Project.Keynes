# Layered papercut atlas UI QA

The menu atlas review set is generated by `tests/ui/menu_atlas_visual_qa.gd` with
Godot 4.6.2. It covers the home, new-game, load, and settings pages at
1280x720, 1366x768, 1920x1080, and 2560x1080, each at 100%, 125%, and 150%
UI scale. The run reported `0 failures`; action controls stayed inside the
viewport bounds.

The source/reference comparison set is kept beside the generated captures in
`C:/Users/hkinghuang/.codex/visualizations/2026/10/14/01a139d1-b1ae-7112-934b-1364ccd62330/menu_atlas_review`.
The current implementation uses the versioned ImageGen assets in
`assets/ui/menu_atlas_v1/` and the independent `menu_atlas_theme.tres` theme.

Loading validation:

- `tests/runtime/native_loading_tasks_test.gd`: 0 failures; generation, packed height/flow, detail scatter, cancellation/ownership, and catalog snapshot parity passed.
- `tests/world/cooperative_world_generation_test.gd`: standard 60x40 and large 100x64 runs passed the P95 33 ms budget and the 100 ms generation heartbeat ceiling.
- `tests/ui/loading_player_frame_qa.gd`: the real Forward Mobile player path reaches `world_ready`, but the current cold render still records a 793.7 ms maximum frame gap on the RTX 4080 machine. The report identifies the gap as the first world upload/pipeline frame (`canvas=1`); this remains an acceptance risk rather than a claimed pass.

The animation clip is produced with `tests/ui/loading_overlay_clip.gd`; encode the
captured PNG sequence at 15 fps with ffmpeg for review. `reduce_motion` keeps
the real progress value and fade while disabling parallax and looping survey
motion.
