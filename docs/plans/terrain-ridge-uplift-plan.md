### 1.2 问题

1. **脊在侵蚀之后**：§5 的加法只看噪声、本格海拔和本格坡度，与 §2.4 刚算出的汇水面积无关。
   结果是脊线横跨河谷、在谷中筑坝。
2. **筑坝的连锁后果**：post-base 的 Priority-Flood（`world_ext_generate.cpp` Hydrologic correction）
   会把被坝住的谷识别成湖盆或迫使河流绕行；§5b 只回填 below-sea 小洼地，管不到 above-sea 的坝后盆地。

   代码靠 p99 膝点压缩（765-791）收顶，这会把高处压成平顶——
   [terrain-density-diagnosis.md](../terrain-density-diagnosis.md) 原因 6「分水岭平坦高海拔 → 高原候选」与此一致。
4. **受体是 Priority-Flood 的「关闭者」**（741 行 `down[ni] = cur`），不是最陡下降；
   hex D6 上流路易顺格向走直线或锯齿。
5. **热力坍塌太弱**（2 轮、talus 0.04），且就地扫描、结果依赖遍历顺序（确定，但与方向相关）。

### 3.2 脊信号作为抬升场

隐式 SPL 的准平衡是逐格 `E_i − E_rcv = U_i / C_i`，`C_i ∝ A_i^m`：

- 脊信号强、汇水小的格：`U/C` 大 → 高出下游多 → **脊**；
- 穿过山带的大河：`A` 大、`C` 大 → `U/C` 小 → 抬升被下切抵消 → **峡谷**（先成河）；
- 地台上无脊信号处：只有 `u_relief·relief0` 的轻微抬升 → 保持平缓。

这正是 Cordonnier 2016 用抬升图控制山系布局的做法：**噪声决定「哪里在抬」，水系决定「抬出什么形状」**。

原实现（G1 之前）把脊**只**放进逐轮抬升项：

```
U_i = spl_uplift_rate · relief0_i + spl_ridge_uplift · ridge_add_i     （每轮）
```

`ridge_add_i` 沿用现 §5 公式但输入换成 E0（冻结）；`spl_ridge_uplift` 是**每轮**系数，
14 轮累计抬升约 `14 · spl_ridge_uplift · ridge_add`，由 §4 标定到与改动前的 p99 陆地高度一致。

**G1 修改：拆成「初始地形」与「逐轮抬升」两部分（2026-11-18，S7 T6 已实现）**

原实现有一个机制缺陷：**第 1 轮建树时 E 里还没有脊**，水网按 E0 组织；之后每轮抬升量很小，
14 轮内分水岭迁移是慢过程 ⇒ 脊抬升没能改变「哪里是分水岭」。现在把 14 轮的脊量按 `f_pre` 提前预叠：

```
E_init = E0 + f_pre · (spl_iters · spl_ridge_uplift) · ridge_add      （§R 之后、第 1 轮建树之前，仅陆地）
U_i    = spl_uplift_rate · relief0_i + (1 − f_pre) · spl_ridge_uplift · ridge_add_i    （每轮）
```

- `f_pre = spl_ridge_prestamp_frac`（新 profile 键，**默认 0.5**，`@export_range(0.0, 1.0, 0.05)`）。
- 两项相加仍等于 `spl_iters · spl_ridge_uplift · ridge_add` ⇒ `f_pre` 只改变「脊在第几轮出现」，**不改变总脊量**；
  **`f_pre = 0` 时与 G1 之前逐位一致**（两个种子 hash 完全匹配 `51a893b7a6b45835` / `22149fd9ffeee585`）。
- E_init 写入后立刻做一次**局部填洼**（Priority-Flood，种子 = 南北边缘 ∪ 水体，`+1e-3`，水体逐位不动），
  防止预叠脊在谷里筑坝 —— 这正是旧版「脊在 SPL 后叠加」造坝的反面，必须在建树前消掉。
- 代价：`f_pre` 0 → 0.75 时 base pass **+1.2~1.7 ms @60×40**，`land_h` p50/p90 **基本不动**（预叠脊没有把高度分布打散）。
- 三处同源（漏传即隐形陷阱）：`climate_profile.gd` 默认 0.5、`native_generation_bridge.gd` 的 keys 数组、C++ 兜底常量 0.5。
- **效果如实记录**：G1 只解决「建树时水网不知道脊在哪」，**是否把分水岭拉到脊上并未验证** ——
  T4（在 G1 落地之前完成）的同口径整版复核只有 **dM1' = +0.0443（< +0.05）**、
  `M1' − 零假设` **+0.102（< 0.15）**（§6.2.5），**G1 之后未重测**；
  `f_pre` 对 M1' / M2 的逐档作用也**未测**（只测了耗时与 p50/p90），默认值沿用计划初值 0.5，不得当作已调优。

### 3.3 SPL 内的坡面扩散

每轮下切后做一步显式线性扩散（hex 6 邻 Laplacian）：

```
E'_i = E_i + κ · Σ_k (E_nb_k − E_i) / 6      仅陆地；海洋邻居按其高度作固定边界
```

- `κ = spl_hillslope_diffusion`（默认 0.08，稳定上限 < 1，留足余量）。
- 扩散会抬高谷底、削低凸脊（质量守恒），cell 层没有单调约束；下一轮 SPL 再下切谷底——
  这就是 SPL + 扩散的标准耦合，平衡态是凸脊 + 凹河道剖面。
- 双缓冲（读 E 写 E'），与遍历方向无关。
- 目的：圆脊、去尖，让高度预算只需线性缩放，**取消膝点硬压缩**（它是平顶的来源）。

### 3.4 最陡受体

```
Priority-Flood 照旧给出 filled 与出栈序 proc（单调不减）
rcv[i] = argmax_d (filled[i] − filled[nb_d])，仅取严格更低者；平局取 d 小者；无则沿用关闭者（平地 ε 路径）
```

`filled` 严格更低的邻居必然先出栈，`proc` 仍是拓扑序；`area` 累积与下切循环无需改动。
（post-base 的 `hydro_parent` 有自己的 Priority-Flood，本计划不动。）

**诊断键（2026-11-18，S7 T12）**：`spl_steepest_receiver`（raw profile 键，**默认 `true`**）保留为**消融诊断键** ——
`= 0` 时回落到 Priority-Flood 的「关闭者」受体、地形确实改变（elevation hash `4c944a48e0f8cb69` ≠ 默认），
S7 T5 的 **A4 组**就是用它跑的；生产不传该键即等价于本节的最陡受体，**对出货零行为变化**（不改默认、不进生产 profile）。

### 3.5 高度预算

现状：SPL 末尾 p99 膝点压缩 + §5 的 p99 二分预算两次收顶。
新：§2.4' 末尾一次「仅缩放」——对陆地相对海平面高度乘统一系数，使 p99 落在 `soft_max`；
仍保留 §5' 的指数软上限（只作用于极少数尖峰）。单调缩放保持高程序，地貌分类阈值的含义不变。

#### 6.2.4 跨版本不可比：两版 `ridge_add` 不是同一个场（2026-11-18）

这是跟进计划 S3 查出的**真因**，也是「M2b 从 5.0 涨到 41.0」与「M1 变正」这两件事的根源：
**`ridge_add` 在两版之间不是同一个场** —— 旧版在 `§5'`（SPL 之后）用**最终 E** 算，新版在 `§R`（SPL 之前）用 **E0** 算。
实测（同种子；旧版用换 DLL 法取得）：

| 尺寸 / 种子 | ridge 陆地 p75 旧 → 新 | 高脊格集合 Jaccard | 场 Pearson |
|---|---|---:|---:|
| 60×40 / …718 | 0.0369 → **0.1602** | 0.367 | 0.410 |
| 60×40 / …719 | 0.0407 → **0.2099** | 0.310 | 0.399 |
| 200×150 / …718 | 0.0602 → **0.1753** | 0.346 | 0.492 |
| 200×150 / …719 | 0.0584 → **0.1641** | 0.428 | 0.518 |

⇒ 新场幅值大 **3–5 倍**、与旧场相关仅 **0.40–0.52**、「高脊格」集合只有 **31–43%** 是同一批格
⇒ 判据的格子集合换了 60%+，**M1 / M2b 的「旧基线 vs 新值」比较本身不成立**（§6.2.2 的 M2b「变差」因此不能归因于任何一处工序）。
⇒ **规矩**：结构指标只能做**同版本内**对照（vs 零假设、vs 关 knob），跨版本必须声明不可比；
需要跨版本时用换 DLL 法并同时给出「判据集合一致度」（Jaccard），否则数字不可引用。
⇒ **可用的衍生值**：幅值对齐应是 `u ≈ 0.071 / 3.5 ≈ 0.020`（当前 0.03 约等于旧版总脊抬升的 1.5 倍），
交跟进计划 §6.3 作联合重标的初值改正。
（**S7 T9 已重标**：在 G1 之上扫 u ∈ {0.010, 0.015, 0.020} 后落地 **0.010**、不是 0.020 ——
因为大图 p50 的偏差不是 u / rate 能修的，选点改按「p90 全达标里 pits 最低」，见 §4.3。）

## 附 B 未达标项与后续建议

### B-1 M1「脊是分水岭」为什么没有改善

> **（2026-11-18 跟进修订）** 本节的归因方向仍成立，但结论已被 §6.2.3 取代：M1 换成 **M1'** 后实测
> 0.3792 vs 零假设 0.3097 ⇒ **只高 +0.0695，仍未达标**；且本节引用的「旧基线 vs 新值」跨版本不可比（§6.2.4）。
> 因此「加大 u 让 M1 更负」这条路径不该再作为下一步的首选 —— 先把同版本判据定下来。

`ridge_add` 是**静态噪声场**（§R 在冻结的 E0 上算出，之后不再随水系变化）；它与「最终地表格 `log A`」的相关性
主要由**最终水系**决定。新实现把脊抬高后，抬升场的强弱仍由噪声在空间上铺开，而河流在 D6 上的走向由整片地形
（含 `relief0` 抬升项、扩散、最陡受体）共同决定 ⇒ **抬高脊线并不改变 Spearman 的符号**，
只是让部分谷地也跟着抬高。因此 M1 从 −0.2863 → −0.2669（更「正」= 变差），但幅度有限。

要让脊真正成为分水岭，需要**更大的 u**：§4.1 扫描显示 u=0.10 时 M1 方向确实更负，但 land p90 被抬到 +24% 基线、
闭合洼地回升到 543.4（相对 u=0.03 的 431.9 明显回升）⇒ 这条路径在本轮被否决，不是遗漏。

### B-2 `highland_river_count` −55% / −73%：预期方向，非缺陷

> **（2026-11-18 跟进修订）** 本节归因只对了一半：实测高地格数只降 12.7% / 16.9%，真实变化是
> **「高地源流（headwater）变少」**，判据已在 §6.3.2 正式修订。下面保留原记录。

见 §6.3.2。归因：受体从 Priority-Flood「关闭者」换成最陡下降后，河流从贴脊路径回到谷底，所在格 landform
不再是高地类。连带 landform HILL 占比 200×150 **28.2% → 23.6%（−16%）**、PLAINS **+23%**
（60×40 HILL 14.7% → 16.9%）。**硬门禁仍全绿**（`bio_occupancy_pass_test` 86/0）。
建议下一轮把该行判据改为「允许下降 + 河流格位于局地谷底作为正向判据」（本轮未改判据，故记超带）。

### B-3 M5「平顶率」为什么变差

> **（2026-11-18 跟进修订）本节结论作废**：M5_p90 的方向本身是错的 —— 实测 M5a = 0.7240、M5b ≈ 0.0019
> ⇒ **山顶是圆的，不是平的**；「变差」是「扩散把局地起伏磨小」被误读成「变平」的伪信号（§6.2.3）。
> 下面这段分析保留为历史记录，不要再据此回退任何参数。

膝点硬压缩（平顶的已知来源）**确实已删除**、坡面扩散也按计划加入，但实测**高地平坦率反而上升**
（M5_p90 0.0000 → 0.01095、0.0016 → 0.0509）。可能的方向（**推断，未验证**）：
扩散抬高谷底的同时把「高地」的 p90 门槛整体上移，而 `u=0.03` 的脊抬升让高地更平缓；`spl_uplift_rate` 下调到 0.08
使整体起伏变小。**下一轮应先做归因实验（单独扫 κ 与 rate）再决定是否回退**，不要只靠调阈值让门禁变绿。

### B-4 下一轮建议（按优先级）

1. **M1 归因与重标**：`spl_ridge_uplift` 与 `spl_uplift_rate` **联合**重标（单独拉 u 会同时抬高 p90、恶化洼地）；
   并考虑**只在分水岭格上施加抬升**（用首轮的 `A` 或填洼面判定分水岭，代替全图 `ridge_add` 加权）。
   **（S7 进展：联合重标已由 T9 做 —— u = 0.010、rate 保持 0.08，§4.3；但大图 p50 的 −18.7% 未解决。
   「只在分水岭格上施加抬升」仍未做。）**
2. **M5 / M2b 联合诊断**：两者同时变差，怀疑同一机制（脊线附近被抬平又保留闭合洼地）；
   建议先加「脊线邻域的 p90 起伏」与「洼地到脊线距离」两个诊断量。
3. **分布带补测**：terrain 直方图、`peak_count` / `plateau_count`、MOUNTAIN/PEAK 占比、`desert_class_count`、
   雨影覆盖、起始格可用率、资源总量本轮**均未测**，需补 A/B。
4. **判据修订**：`highland_river_count`（§6.3.2）与 M5 口径（已改为 M5_p90）应在下一轮评审时正式固化到 §6.2 / §6.3。
5. **A/B 截图与 perf-validation 基线**：本轮均未做（未测），K5 / K6 的验证仍欠。
